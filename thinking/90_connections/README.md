## Cách đọc casebook

Mỗi case đi theo cùng một grammar:

```text
Situation
→ tempting shortcut
→ frame the actual question
→ select tools
→ inspect evidence
→ model uncertainty
→ consider incentives / system effects
→ choose action or update rule
→ handoff to canonical domain
```

Mục tiêu không phải tạo một checklist dài phải dùng mọi lần. Mục tiêu là luyện **tool selection**: dùng đủ công cụ để tránh failure mode chính, nhưng không biến một quyết định nhỏ thành research project.

## Three-level depth

### Quick pass — 30 giây

```text
What is the claim / decision?
What is the strongest alternative explanation?
What is uncertain?
What would change my mind?
```

### Normal pass — vài phút

Thêm base rate, source quality, opportunity cost, main downside, incentives và second-order effects.

### Deep pass — quyết định material

Thêm scenario ranges, expected value, causal evidence, value of information, premortem, sensitivity analysis và explicit review rule.

Depth phải tỷ lệ với stakes, irreversibility và uncertainty.

## Practice layer

Nếu casebook giúp nhận ra **tool nào cần dùng**, [`../practice/`](../practice/README.md) luyện **cách dùng tool lặp lại** qua calibration/Bayesian updating, sensitivity analysis, scenario stress testing và decision journal/postmortem.

## Boundary

Casebook chỉ dạy reasoning workflow. Khi case chạm domain chuyên môn — medical, legal, investing, engineering, research, politics/public policy — reader phải handoff về canonical domain và nguồn evidence thích hợp. Thinking tools không thay thế subject-matter expertise.
