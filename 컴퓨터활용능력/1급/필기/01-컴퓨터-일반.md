## 1. 컴퓨터 시스템 구조 및 CPU (Kiến trúc máy tính & Vi xử lý CPU)

### 1.1 중앙처리장치(CPU)의 3대 핵심 구성 요소 (3 thành phần cốt lõi của CPU)

**[한국어 핵심 개념 및 출제 원리]**
> 중앙처리장치(CPU: Central Processing Unit)는 컴퓨터 시스템의 두뇌에 해당하며, 제어장치(Control Unit), 산술논리연산장치(ALU: Arithmetic Logic Unit), 그리고 내부 레지스터(Registers)의 3대 핵심 요소로 구성됩니다.
> - **제어장치(Control Unit, CU):** 주기억장치에서 명령어를 읽어 해독한 후, 각 장치에 제어 신호를 보내 명령을 실행하도록 통제하는 장치입니다.
> - **산술논리연산장치(ALU):** 산술 연산(덧셈, 뺄셈, 곱셈, 나눗셈)과 논리 연산(AND, OR, NOT, 크기 비교 등)을 실제로 수행하는 회로입니다.
> - **레지스터(Registers):** CPU 내부에서 데이터와 명령어를 일시적으로 보관하는 가장 빠른 초고속 임시 기억장치입니다.

**[Tiếng Việt diễn giải & Cơ chế chuyên sâu]**
Vi xử lý CPU là trung tâm điều khiển và xử lý dữ liệu của máy tính:
1. **Khối điều khiển (CU — Control Unit):** Không trực tiếp tính toán dữ liệu mà đóng vai trò "nhạc trưởng". CU chịu trách nhiệm nạp lệnh từ RAM, phân tích mã lệnh (Op-Code), đồng bộ hóa xung nhịp hệ thống và phát tín hiệu điều khiển vi mô tới ALU, Bus, và bộ nhớ.
2. **Khối số học & logic (ALU — Arithmetic Logic Unit):** Trực tiếp xử lý dữ liệu nhị phân. Gồm các mạch cộng (Adder), mạch dịch (Shifter), và các cổng logic để thực hiện phép tính số học và so sánh logic (`>`, `<`, `=`, `AND`, `OR`).
3. **Tập thanh ghi (Registers):** Được chế tạo từ các mạch Flip-Flop hoặc SRAM nằm trực tiếp trên phiến silicon của CPU. Tốc độ truy xuất của thanh ghi tính bằng chu kỳ nano/pico-giây, nhanh nhất trong toàn bộ hệ thống máy tính.

```
                    ┌────────────────────────────────────────────────────────┐
                    │              CPU (중앙처리장치)                        │
                    │                                                        │
                    │  ┌─────────────────────────┐  ┌─────────────────────┐  │
                    │  │   Control Unit (CU)     │  │     ALU             │  │
                    │  │   (제어장치)            │  │     (산술논리연산장치) │  │
                    │  │  • PC      • IR         │  │  • AC (누산기)       │  │
                    │  │  • Decoder • Encoder    │  │  • Adder  • Status  │  │
                    │  └────────────┬────────────┘  └──────────┬──────────┘  │
                    │               │                          │             │
                    │  ┌────────────┴──────────────────────────┴──────────┐  │
                    │  │          Registers (레지스터)                    │  │
                    │  │          • MAR          • MBR                    │  │
                    │  └──────────────────────────────────────────────────┘  │
                    └────────────────────────────────────────────────────────┘
```

### 1.2 주요 레지스터의 기능 분류 (Phân loại chi tiết các thanh ghi trong CPU)

**[한국어 필수 암기 표 및 기출 지문]**
> 대한상공회의소 기출문제에서는 각 레지스터가 **제어장치 소속인지, ALU 소속인지**를 묻거나, **"다음에 실행할 명령어의 주소를 기억하는 레지스터는?"**과 같은 정의 매칭 문제가 매우 빈번하게 출제됩니다.

| 레지스터 명칭 (Tên thanh ghi) | 약어 | 소속 | 한국어 기능 정의 (Định nghĩa tiếng Hàn) | Tiếng Việt giải thích chức năng |
|---|:---:|:---:|---|---|
| **Program Counter** | **PC** | 제어장치 | **다음에 실행할 명령어의 번지(주소)를 기억하는 레지스터** | Lưu địa chỉ ô nhớ của lệnh tiếp theo sẽ thực thi. Tự động tăng sau khi nạp lệnh. |
| **Instruction Register** | **IR** | 제어장치 | **현재 실행 중인 명령어를 기억하는 레지스터** | Lưu mã lệnh hiện hành để chuyển sang bộ giải mã lệnh (Instruction Decoder). |
| **Instruction Decoder** | - | 제어장치 | 명령어 레지스터(IR)의 명령 코드를 해독하여 제어 신호를 발생시키는 회로 | Giải mã mã thao tác (Op-Code) thành các tín hiệu vi mô điều khiển phần cứng. |
| **Encoder (부호기)** | - | 제어장치 | 해독된 명령을 바탕으로 각 장치에 보낼 실제 제어 신호를 생성하는 회로 | Tạo và phát các xung nhịp điều khiển cụ thể đến bus hệ thống. |
| **Memory Address Register** | **MAR** | 제어/버스 | CPU가 읽거나 쓰고자 하는 **주기억장치의 주소 번지를 기억하는 레지스터** | Lưu địa chỉ ô nhớ RAM mà CPU chuẩn bị đọc hoặc ghi dữ liệu. |
| **Memory Buffer Register** | **MBR** | 제어/버스 | 주기억장치에서 읽어오거나 기록할 **데이터를 임시로 기억하는 레지스터** | Bộ đệm lưu dữ liệu thực tế đọc từ RAM vào hoặc chuẩn bị ghi ra RAM. |
| **Accumulator (누산기)** | **AC** | ALU | **산술 및 논리 연산의 결과(중간 계산 값)를 일시적으로 기억하는 레지스터** | Chứa kết quả trung gian của các phép toán do ALU thực hiện. |
| **Program Status Word** | **PSW** | ALU/제어 | 연산 결과의 상태(부호, 0, 오버플로, 캐리, 인터럽트 등)를 나타내는 상태 플래그 레지스터 | Lưu các cờ trạng thái hệ thống: cờ âm (Sign), cờ 0 (Zero), cờ tràn (Overflow). |

### 1.3 명령어 실행 주기 (Chu kỳ thực thi lệnh của CPU)

**[한국어 핵심 개념]**
> CPU가 하나의 명령어를 처리하는 과정은 주기적으로 반복되며, 이를 **명령어 실행 주기(Instruction Cycle)**라고 합니다.
> 1. **인출 주기(Fetch Cycle):** 주기억장치에서 PC가 가리키는 주소의 명령어를 CPU 내부의 IR로 가져오는 단계.
> 2. **간접 주기(Indirect Cycle):** 명령어의 번지부가 간접 주소(Indirect Address)인 경우, 유효 주소를 구하기 위해 주기억장치에 한 번 더 접근하는 단계.
> 3. **실행 주기(Execute Cycle):** 해독된 명령어를 바탕으로 실제 연산(ALU)을 수행하거나 데이터를 제어하는 단계.
> 4. **인터럽트 주기(Interrupt Cycle):** 명령어 실행 중 예기치 않은 하드웨어/소프트웨어 예외가 발생했을 때 이를 처리하고 원래 상태로 복귀하는 단계.

**[Tiếng Việt giải thích cơ chế]**
Một lệnh máy tính trải qua 4 giai đoạn logic khép kín:
- **Fetch:** $PC \to MAR \to Memory \to MBR \to IR$; đồng thời $PC = PC + 1$.
- **Indirect:** Nếu cờ địa chỉ là Indirect (địa chỉ gián tiếp), CPU lấy địa chỉ từ MBR đưa vào MAR để nạp địa chỉ thực sự của toán hạng (Effective Address).
- **Execute:** ALU tính toán dữ liệu hoặc CU di chuyển dữ liệu giữa các thanh ghi.
- **Interrupt:** CPU lưu trạng thái thanh ghi và PC hiện tại vào Stack, nạp địa chỉ hàm xử lý ngắt (Interrupt Service Routine - ISR) vào PC để giải quyết sự cố, sau đó quay lại tiếp tục.

### 1.4 CISC vs RISC 심층 비교 (So sánh đối kháng CISC vs RISC)

**[한국어 기출 핵심 비교 분석]**
> KCCI 1급 필기 시험에서 가장 높은 빈도로 출제되는 하드웨어 아키텍처 비교표입니다. 명령어의 수, 길이, 주소 지정 방식, 파이프라이닝 적용 여부를 반드시 대비해야 합니다.

| 비교 항목 (Tiêu chí so sánh) | CISC (Complex Instruction Set Computer) | RISC (Reduced Instruction Set Computer) |
|---|---|---|
| **한국어 명칭** | **복잡 명령어 집합 컴퓨터** | **축소 명령어 집합 컴퓨터** |
| **명령어 수 (Số lệnh)** | **매우 많음** (복잡하고 다양한 기능의 명령어 제공) | **적음** (자주 쓰이는 기본 명령어 위주로 최소화) |
| **명령어 길이 (Độ dài lệnh)** | **가변 길이** (명령어마다 길이가 다름) | **고정 길이** (명령어 길이가 일정하여 디코딩 빠름) |
| **실행 클록 수 (CPI)** | 하나의 명령어를 실행하는 데 **여러 클록 사이클** 소요 | 대부분의 명령어가 **1 클록 사이클**에 실행 완료 |
| **레지스터 수 (Số thanh ghi)** | 상대적으로 적음 | **매우 많음** (범용 레지스터 다수 탑재) |
| **주소 지정 방식 (Addressing Mode)** | 매우 다양하고 복잡함 | 단순함 (기억장치 접근은 `LOAD`/`STORE` 명령으로만 한정) |
| **파이프라이닝 (Pipelining)** | 명령어 길이가 달라 파이프라이닝 구현이 어려움 | 명령어 구조가 균일하여 **파이프라이닝 효율이 극대화됨** |
| **전력 소비 및 가격** | 전력 소모가 크고 발열이 많음 (고성능 PC, x86/Intel/AMD) | 저전력, 저발열, 가격 저렴 (스마트폰, 임베디드, ARM, Apple Silicon) |

## 2. 기억장치 계층 구조 및 가상기억장치 (Hệ thống bộ nhớ & Bộ nhớ ảo)

### 2.1 주기억장치: ROM vs RAM

**[한국어 핵심 개념]**
> - **ROM(Read Only Memory):** 비휘발성(Non-Volatile) 메모리로 전원이 꺼져도 내용이 지워지지 않으며, 컴퓨터 부팅에 필요한 기본 입출력 시스템(BIOS/UEFI), 자가 진단 프로그램(POST)을 저장합니다.
>   * **Mask ROM:** 제조 공정에서 데이터를 영구 기록한 것으로 수정 불가.
>   * **PROM:** 사용자가 전용 라이터기로 단 한 번만 기록 가능.
>   * **EPROM:** 자외선(UV)을 쬐어 기록된 내용을 여러 번 지우고 다시 쓸 수 있음.
>   * **EEPROM:** 전기적인 신호로 내용을 지우고 다시 기록 가능 (현대 플래시 메모리 및 메인보드 BIOS의 기반).
> - **RAM(Random Access Memory):** 휘발성(Volatile) 메모리로 전원이 차단되면 저장된 데이터가 모두 소멸되며, 실행 중인 프로그램과 데이터를 일시 적재합니다.

**[SRAM과 DRAM의 핵심 비교 (So sánh SRAM vs DRAM)]**

| 비교 항목 | SRAM (Static RAM / 정적 램) | DRAM (Dynamic RAM / 동적 램) |
|---|---|---|
| **소자 구조** | 플립플롭(Flip-Flop) 회로 | 콘덴서(Capacitor, 축전기) |
| **재충전 (Refresh)** | **재충전이 필요 없음** | 전하가 방전되므로 **주기적인 재충전(Refresh) 필수** |
| **속도** | **매우 빠름** (DRAM 대비 5~10배) | 보통 |
| **용량 및 집적도** | 구조가 복잡하여 대용량 제작 어려움 (집적도 낮음) | 구조가 단순하여 대용량 집적 용이 (집적도 높음) |
| **소비 전력 & 가격** | 소비 전력 큼, 가격이 매우 비쌈 | 소비 전력 적음, 가격이 저렴 |
| **주요 용도 (Ứng dụng)** | **CPU 내부 캐시 메모리 (L1, L2, L3 Cache)** | **컴퓨터 메인 주기억장치 (PC RAM 모듈)** |

### 2.2 캐시 메모리(Cache Memory)의 구조 및 매핑 (Bộ nhớ đệm Cache & Ánh xạ)

**[한국어 핵심 개념 및 출제 원리]**
> 캐시 메모리는 **CPU(중앙처리장치)와 주기억장치(RAM) 사이의 속도 격차를 완화**하기 위해 고안된 고속 SRAM 버퍼입니다.
> - **적중률(Hit Ratio):** CPU가 필요로 하는 데이터가 캐시 메모리에 존재할 확률입니다.
>   $$\text{Hit Ratio} = \frac{\text{캐시 적중 횟수(Hits)}}{\text{전체 메모리 참조 횟수(Hits + Misses)}}$$
>   적중률이 1(100%)에 가까울수록 CPU는 RAM에 접근하지 않고 고속으로 데이터를 처리할 수 있습니다.
> - **캐시 매핑 방식(Cache Mapping):** 주기억장치의 블록을 캐시 슬롯에 배치하는 규칙입니다.
>   1. **직접 매핑(Direct Mapping):** 주기억장치의 특정 블록이 지정된 단 하나의 캐시 라인으로만 매핑되는 방식. 구조가 가장 단순하고 구현 비용이 저렴하지만, 동일 라인을 두고 충돌이 빈번하여 적중률이 낮습니다.
>   2. **연관 매핑(Associative Mapping):** 주기억장치의 블록이 캐시의 어느 라인에나 자유롭게 적재될 수 있는 방식. 충돌이 없어 적중률이 가장 높지만, 캐시 전체를 병렬 검색해야 하므로 하드웨어 회로가 매우 복잡하고 고가입니다.
>   3. **세트 연관 매핑(Set-Associative Mapping):** 직접 매핑과 연관 매핑을 절충한 방식. 캐시를 여러 개의 세트(Set)로 나누고, 각 세트 내부에서는 연관 매핑 방식을 적용합니다. (현대 CPU가 가장 널리 채택)
> - **캐시 쓰기 정책(Write Policy):**
>   * **Write-Through(즉시 쓰기):** 캐시와 주기억장치에 데이터를 **동시에 기록**하는 방식. 데이터 일관성이 보장되지만 쓰기 속도가 느립니다.
>   * **Write-Back(나중 쓰기):** 캐시에만 먼저 기록해 두고, 해당 캐시 블록이 교체될 때 주기억장치에 일괄 기록하는 방식. 쓰기 속도는 매우 빠르지만 구현이 복잡하고 일시적인 불일치가 존재합니다.

### 2.3 가상기억장치(Virtual Memory) 및 스래싱(Thrashing)

**[한국어 핵심 개념 및 메커니즘]**
> 가상기억장치는 **주기억장치의 물리적 용량 한계를 극복**하기 위하여 보조기억장치(HDD, SSD)의 일부 영역을 마치 주기억장치인 것처럼 주소 공간을 확장하여 사용하는 기법입니다.
> - **페이징 기법(Paging):** 가상 메모리를 **고정 크기(Fixed size)의 단위인 페이지(Page)**로 분할하고, 주기억장치도 동일한 크기의 프레임(Page Frame)으로 분할하여 매핑하는 방식. 외부 단편화는 발생하지 않으나, **내부 단편화(Internal Fragmentation)**가 발생할 수 있습니다.
> - **세그멘테이션 기법(Segmentation):** 프로그램을 배열, 함수, 모듈과 같은 **논리적 의미 단위인 가변 크기(Variable size)의 세그먼트(Segment)**로 분할하는 방식. 내부 단편화는 방지되지만, **외부 단편화(External Fragmentation)**가 발생할 수 있습니다.
> - **스래싱(Thrashing):** 프로세스가 실행되는 시간보다 **페이지를 교체(Page Swap)하는 데 소모되는 시간이 더 커져서, CPU 이용률이 급격하게 곤두박질치는 심각한 성능 저하 현상**입니다.
> - **스래싱 방지 대책:**
>   1. **워킹 셋(Working Set):** 프로세스가 일정 시간 동안 자주 참조하는 페이지들의 집합을 주기억장치에 지속적으로 상주시켜 페이지 부재(Page Fault)를 방지합니다.
>   2. **페이지 부재 빈도(PFF: Page Fault Frequency):** 페이지 부재율의 상한선과 하한선을 설정하여 프레임 할당량을 동적으로 조절합니다.
> - **참조의 국부성(Locality of Reference):**
>   * **시간 국부성(Temporal Locality):** 최근에 참조된 기억 장소가 가까운 미래에 다시 참조될 가능성이 높은 특성 (예: 반복문 Loop, 서브루틴).
>   * **공간 국부성(Spatial Locality):** 참조된 기억 장소의 인접한 주소들이 연속적으로 참조될 가능성이 높은 특성 (예: 배열 순차 탐색).

## 3. 시스템 버스 및 RAID (Bus hệ thống & Mảng đĩa RAID)

### 3.1 시스템 버스(System Bus) 3대 분류

**[한국어 개념 및 방향성 분석]**
> - **데이터 버스(Data Bus):** CPU, 메모리, 입출력장치 간에 실제 데이터를 주고받는 통로로, 데이터 이동이 양쪽으로 이루어지므로 **양방향(Bi-directional)** 버스입니다. 데이터 버스의 폭(Width)은 CPU가 한 번에 처리할 수 있는 워드(Word) 크기(32비트, 64비트)를 결정합니다.
> - **주소 버스(Address Bus):** CPU가 주기억장치나 입출력장치의 특정 메모리 위치를 지정하기 위해 번지를 전달하는 통로로, CPU에서 주변 장치로만 주소가 전달되므로 **단방향(Uni-directional)** 버스입니다. 주소 버스의 폭은 시스템이 접근할 수 있는 최대 주기억장치 용량($2^n$)을 결정합니다.
> - **제어 버스(Control Bus):** CPU가 시스템 구성 요소들에게 읽기/쓰기 동작을 지시하고, 주변 장치에서 인터럽트 신호를 CPU로 보내는 통로로, **양방향(Bi-directional)**으로 신호가 오갑니다.

---

### 3.2 RAID(Redundant Array of Independent Disks) 기술 비교

**[한국어 핵심 개념]**
> RAID는 여러 개의 물리적 하드디스크를 하나의 논리적 드라이브로 묶어 속도 향상, 안정성 확보, 용량 확장을 달성하는 디스크 어레이 기술입니다.

| RAID 레벨 | 기술 방식 (한국어) | 핵심 원리 및 특징 | Tiếng Việt giải thích |
|---|---|---|---|
| **RAID 0** | **스트라이핑 (Striping)** | 데이터를 여러 디스크에 나누어 병렬로 분산 기록. **속도는 가장 빠르나 장애 복구 기능(오류 검출/패리티)이 없어 디스크 1개만 고장 나도 전체 데이터 손실.** | Ghi dữ liệu xen kẽ song song. Tốc độ đọc/ghi cao nhất nhưng không có khả năng chịu lỗi. |
| **RAID 1** | **미러링 (Mirroring)** | 동일한 데이터를 다른 디스크에 완전히 똑같이 복사하여 저장. **안정성은 최고 수준이나 디스크 가용 용량이 50%로 절반만 사용 가능하여 비용이 높음.** | Sao chép đối xứng toàn bộ dữ liệu. Độ tin cậy tối đa nhưng lãng phí 50% dung lượng đĩa. |
| **RAID 5** | **패리티 분산 (Distributed Parity)** | 데이터와 오류 검출용 패리티(Parity) 정보를 모든 디스크에 분산 저장. **최소 3개 이상의 디스크가 필요하며, 1개의 디스크가 고장 나도 패리티를 통해 실시간 데이터 복구 가능.** (성능과 경제성의 최적 절충안) | Phân tán cả dữ liệu và Parity trên tối thiểu 3 ổ cứng. Cho phép hỏng 1 ổ cứng mà không mất dữ liệu. |

## 4. Windows 10/11 고급 운영체제 관리 (Hệ điều hành Windows chuyên sâu)

### 4.1 레지스트리(Registry) 5대 루트 키 구조

**[한국어 핵심 개념 및 출제 기준]**
> Windows 레지스트리는 시스템 하드웨어, 설치된 소프트웨어, 사용자 환경 설정, 시스템 보안 정책 등을 체계적으로 보관하는 계층적 데이터베이스입니다. `Win + R` 실행 창에서 `regedit` 명령어로 편집기를 실행합니다.

1. **`HKEY_CLASSES_ROOT` (HKCR):** 파일 확장자 연결 정보(예: `.xlsx` 파일 실행 시 Excel 연결) 및 OLE/COM 클래스 등록 정보를 관리합니다.
2. **`HKEY_CURRENT_USER` (HKCU):** 현재 로그인한 사용자의 개인 환경 설정(바탕화면 배경, 테마, 마우스 설정, 개인용 응용 프로그램 설정)을 관리합니다.
3. **`HKEY_LOCAL_MACHINE` (HKLM):** 컴퓨터의 모든 사용자에게 공통으로 적용되는 시스템 하드웨어 드라이버, 네트워크 카드, 설치된 전역 소프트웨어 정보를 보관합니다.
4. **`HKEY_USERS` (HKU):** 시스템에 등록된 모든 사용자 계정 프로필의 정보를 보관하며, 현재 로그인 사용자의 정보는 HKCU로 링크됩니다.
5. **`HKEY_CURRENT_CONFIG` (HKCC):** 컴퓨터가 부팅될 때 현재 사용 중인 하드웨어 프로필(디스플레이 해상도, 프린터 구성 등) 정보를 관리합니다.

---

### 4.2 시스템 관리 및 진단 도구 (Event Viewer & Task Manager)

**[한국어 실무 진단 도구 정리]**
- **작업 관리자(Task Manager - `Ctrl + Shift + Esc`):**
  * 실행 중인 앱, 백그라운드 프로세스, CPU/메모리/디스크/네트워크/GPU 사용률을 실시간 모니터링합니다.
  * 응답하지 않는 프로그램을 강제 종료(작업 끝내기)할 수 있습니다.
  * **시작 프로그램(Startup Apps) 탭:** 윈도우 부팅 시 자동 실행되는 프로그램들의 시작 시 영향을 확인하고 사용/사용 안 함을 설정하여 부팅 속도를 최적화합니다.
- **이벤트 뷰어(Event Viewer - `eventvwr`):**
  * 시스템에서 발생하는 모든 주요 이벤트(하드웨어 오류, 서비스 시작/중지 실패, 보안 감사 성공/실패)를 로그 파일(`.evtx`)로 기록하고 추적합니다.
  * 3대 핵심 Windows 로그: **응용 프로그램 로그**, **보안 로그**(로그온/로그오프 감사), **시스템 로그**(시스템 드라이버 및 서비스 오류).
- **안전 모드(Safe Mode):**
  * 컴퓨터에 바이러스 감염이나 드라이버 충돌로 부팅이 되지 않을 때, 가장 기본적인 최소 드라이버(기본 VGA, 키보드, 마우스)만을 로드하여 부팅하는 진단용 환경입니다.

## 5. 컴퓨터 네트워크 및 통신 프로토콜 (Mạng máy tính & Giao thức TCP/IP)

### 5.1 OSI 7계층과 TCP/IP 4계층 매핑 (Mô hình OSI 7 tầng vs TCP/IP)

**[한국어 필수 매핑 표]**

```
┌─────────────────────────────────┐                 ┌───────────────────────────┐
│        OSI 7계층 (OSI 7 Layers) │                 │ TCP/IP 4계층 (TCP/IP)     │
├─────────────────────────────────┤                 ├───────────────────────────┤
│ 7. 응용 계층 (Application)      │ ───┐            │                           │
│ 6. 표현 계층 (Presentation)     │ ───┼──────────> │ 4. 응용 계층 (Application)│
│ 5. 세션 계층 (Session)          │ ───┘            │    (HTTP, FTP, DNS, DHCP) │
├─────────────────────────────────┤                 ├───────────────────────────┤
│ 4. 전송 계층 (Transport)        │ ──────────────> │ 3. 전송 계층 (Transport)  │
│                                 │                 │    (TCP, UDP)             │
├─────────────────────────────────┤                 ├───────────────────────────┤
│ 3. 네트워크 계층 (Network)      │ ──────────────> │ 2. 인터넷 계층 (Internet) │
│                                 │                 │    (IP, ARP, RARP, ICMP)  │
├─────────────────────────────────┤                 ├───────────────────────────┤
│ 2. 데이터 링크 계층 (Data Link) │ ───┐            │ 1. 네트워크 액세스 계층   │
│ 1. 물리 계층 (Physical)         │ ───┴──────────> │    (Ethernet, MAC, Wi-Fi) │
└─────────────────────────────────┘                 └───────────────────────────┘
```

| 계층 | 한국어 명칭 및 역할 정의 | 주요 장비 | 핵심 프로토콜 |
|---|---|---|---|
| **물리 (Physical)** | 전송 매체를 통해 전기적/광학적 비트 신호(0과 1)를 물리적으로 송수신 | 리피터(증폭기), 더미 허브 | RS-232C |
| **데이터 링크** | 인접 노드 간 신뢰성 있는 전송, MAC 주소 기반 물리적 주소 지정, 흐름 제어, 에러 제어 | **스위치(Switch)**, 브리지 | Ethernet (IEEE 802.3), HDLC |
| **네트워크** | 패킷(Packet)의 최적 경로 설정(라우팅), IP 논리적 주소 지정 | **라우터(Router)**, L3 스위치 | **IP, ARP, RARP, ICMP, IGMP** |
| **전송 (Transport)** | 종단 간(End-to-End) 프로세스 간 신뢰성 있는 데이터 전송 및 포트 번호 다중화 | 게이트웨이, L4 스위치 | **TCP (신뢰성/연결형), UDP (비연결형)** |
| **세션 (Session)** | 통신 세션 수립, 유지, 동기화(동기점 Checkpoint 관리) | - | NetBIOS, RPC |
| **표현 (Presentation)** | 데이터 형식 변환, 암호화/복호화, 데이터 압축 | - | JPEG, MPEG, ASCII |
| **응용 (Application)** | 사용자와 응용 프로그램에 직접 네트워크 서비스 제공 | - | **HTTP, HTTPS, FTP, SMTP, POP3, DNS** |

### 5.2 IPv4 vs IPv6 주소 체계 심층 분석

**[한국어 기출 핵심 비교 분석]**
> KCCI 필기 시험에서는 IPv6의 비트 수, 표기 방식, 생략 규칙, 그리고 **"IPv6에는 브로드캐스트가 없다"**는 사실이 반복 출제됩니다.

| 비교 항목 (Tiêu chí) | IPv4 (Internet Protocol v4) | IPv6 (Internet Protocol v6) |
|---|---|---|
| **주소 길이 (Độ dài bit)** | **32비트** ($2^{32} \approx 43\text{억 개}$) | **128비트** ($2^{128} \approx \text{거의 무한대}$) |
| **표기 방식 (Cách biểu diễn)** | 8비트씩 4마디, **10진수**로 표기, **점(`.`)**으로 구분<br>(예: `192.168.0.1`) | 16비트씩 8마디, **16진수**로 표기, **콜론(`:`)**으로 구분<br>(예: `2001:0db8:85a3::8a2e:0370:7334`) |
| **통신 방식 (Chế độ truyền)** | 유니캐스트, 멀티캐스트, **브로드캐스트(Broadcast)** | 유니캐스트, 멀티캐스트, **애니캐스트(Anycast)**<br>**(★ 브로드캐스트 없음!)** |
| **주소 생략 규칙** | 생략 불가 | 각 마디의 앞자리 0은 생략 가능, 연속된 0의 마디는 `::`로 단 한 번만 축약 가능 |
| **보안성** | IPSec 별도 탑재 필요 | **IPSec 프로토콜이 기본 프로토콜에 내장**되어 보안 강화 |
| **품질 제어 (QoS)** | 취약함 | 실시간 흐름 레이블(Flow Label)을 제공하여 멀티미디어 QoS 보장 |

## 6. 정보 보안 및 암호화 기법 (An toàn thông tin & Mật mã học)

### 6.1 대칭키(비밀키) 암호화 vs 비대칭키(공개키) 암호화

**[한국어 필수 비교 정의]**
> - **대칭키(비밀키) 암호화:** 암호화할 때 사용하는 키와 복호화할 때 사용하는 키가 **동일한(하나의) 키**를 사용하는 방식입니다.
> - **비대칭키(공개키) 암호화:** 데이터를 암호화하는 **공개키(Public Key)**와 복호화하는 **비밀키(Private Key)**가 서로 다른 **쌍(Pair)**을 이루는 방식입니다.

| 비교 기준 | 비밀키(대칭키) 암호화 | 공개키(비대칭키) 암호화 |
|---|---|---|
| **키 개수 (Số lượng khóa)** | 1개 (송수신자가 비밀키를 공유) | 2개 쌍 (누구나 아는 공개키 + 본인만 아는 개인키) |
| **암·복호화 속도** | **매우 빠름** (대용량 파일 암호화에 적합) | **느림** (수학적 복잡도가 높아 키 교환이나 서명에 주로 사용) |
| **키 관리의 복잡도** | 사용자가 $n$명일 때 필요한 키 수: **$\frac{n(n-1)}{2}$개** (사용자 증가 시 키 관리 급격히 어려움) | 사용자가 $n$명일 때 필요한 키 수: **$2n$개** (키 관리가 매우 단순함) |
| **디지털 서명 (전자서명)** | 불가능 | **가능** (송신자의 개인키로 서명, 공개키로 검증) |
| **대표 알고리즘** | **DES, 3-DES, AES, SEED(한국표준), ARIA** | **RSA, ECC(타원곡선), ElGamal** |

### 6.2 침입 차단 및 보안 위협 용어 사전

**[한국어 시험 출제 보안 용어 정리]**
- **침입 탐지 시스템(IDS: Intrusion Detection System):** 시스템이나 네트워크에 비인가된 접근이나 침입을 실시간 감시하고 관리자에게 경보를 발송하는 시스템. (오용 탐지: 기존 공격 패턴 Signature 매칭, 이상 탐지: 정상 행동 모델에서 벗어나는 이상 징후 포착)
- **침입 방지 시스템(IPS: Intrusion Prevention System):** 침입을 탐지하는 것에 그치지 않고 비정상 패킷을 능동적으로 실시간 차단하는 보안 시스템.
- **DDoS(분산 서비스 거부 공격: Distributed Denial of Service):** 분산된 수많은 좀비 PC(봇넷)를 조종하여 특정 타깃 서버에 대량의 트래픽을 일시에 전송함으로써 서버 자원을 고갈시켜 정상 서비스를 마비시키는 공격.
- **파밍(Pharming):** 사용자의 PC에 악성코드를 감염시켜 도메인 네임 시스템(DNS) 또는 hosts 파일을 변조함으로써, 사용자가 올바른 URL 주소를 입력해도 가짜 피싱 사이트로 강제 유도하여 금융 정보를 탈취하는 수법.
- **랜섬웨어(Ransomware):** 사용자의 중요 파일들을 암호화하여 열지 못하게 잠근 뒤, 암호 해독 키를 대가로 금전(비트코인 등)을 요구하는 악성 프로그램.
