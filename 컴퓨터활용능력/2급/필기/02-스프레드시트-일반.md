# 02 — 스프레드시트 일반

> **Baseline:** 컴퓨터활용능력 2급 필기 · 2024–2026 출제기준 · Microsoft Office LTSC 2021  
> **핵심 관점:** Excel을 “표를 그리는 프로그램”이 아니라 **셀에 데이터를 저장하고, 수식으로 계산하고, 조건으로 선별하고, 구조로 분석하는 계산 시스템**으로 이해한다.  
> **실기 연결:** 이 과목의 거의 모든 핵심 개념은 2급 실기의 스프레드시트 실무로 이어진다.

## 0. Excel을 하나의 시스템으로 보기

Excel 문제는 메뉴 위치를 외우는 방식만으로는 오래 유지되지 않는다. 가장 먼저 다음 구조를 잡는다.

**Workbook → Worksheet → Cell/Range → Data → Formula/Function → Analysis → Output**

→ Workbook là file Excel; bên trong có nhiều worksheet; worksheet gồm cell; cell chứa dữ liệu hoặc công thức; nhiều cell tạo thành range; từ đó ta tính toán, lọc, phân tích và xuất kết quả.

이 구조를 기준으로 각 기능의 owner를 정하면 혼동이 크게 줄어든다.

- 셀 서식: 데이터를 어떻게 **보이게** 할 것인가
- 수식/함수: 데이터를 어떻게 **계산** 할 것인가
- 정렬/필터: 어떤 행을 어떤 순서로 **볼 것인가**
- 피벗 테이블: 큰 데이터를 어떤 축으로 **요약** 할 것인가
- 차트: 요약 결과를 어떻게 **시각화** 할 것인가

---

# 1. 응용 프로그램 준비

## 1.1 Workbook과 Worksheet

**통합 문서(Workbook)** 는 Excel 파일 전체이고, **워크시트(Worksheet)** 는 그 안의 개별 작업 시트다.  
→ Một file .xlsx có thể chứa nhiều worksheet.

Worksheet는 행(Row)과 열(Column)의 교차점인 셀(Cell)로 구성된다.

- Column: A, B, C ...
- Row: 1, 2, 3 ...
- Cell address: A1, B3, C10

### Active Cell

현재 선택되어 입력 대상이 되는 셀을 활성 셀(Active Cell)이라고 한다.

### Range

여러 셀을 묶은 범위다.

- A1:A10 → 같은 열의 연속 범위
- A1:C3 → 직사각형 범위
- A1,C1,E1 → 비연속 범위

> **연결:** 모든 Excel 기능은 결국 특정 cell 또는 range에 작용하므로, 주소와 범위를 정확히 읽는 것이 수식·필터·차트의 공통 prerequisite다.

---

## 1.2 데이터 유형

Excel 셀에는 숫자, 문자, 날짜/시간, 논리값, 수식 등이 들어갈 수 있다.

### 숫자

계산 가능한 numeric value다.

### 문자 — Text

일반적으로 문자열은 계산 대상이 아니다. 숫자처럼 보이는 값도 텍스트로 저장되면 계산 결과가 달라질 수 있다.

### 날짜와 시간

Excel은 날짜와 시간을 내부적으로 숫자 serial value로 다룬다.  
→ Vì vậy có thể cộng/trừ ngày hoặc tính chênh lệch thời gian.

### 논리값 — Boolean

TRUE와 FALSE를 사용한다. IF, AND, OR 같은 논리 함수의 기반이다.

### 수식 — Formula

등호 = 로 시작한다.

예:
= A1 + B1  
= SUM(A1:A10)

---

## 1.3 입력, 수정, 삭제

데이터 입력과 “서식”을 구분해야 한다.

- Delete/내용 지우기 → 값 또는 수식을 제거
- 서식 지우기 → 표시 형식, 색, 테두리 등을 제거
- 셀 자체 삭제 → 주변 셀이 이동할 수 있음

→ Xóa nội dung khác với xóa cell. Đây là điểm dễ nhầm trong câu hỏi thao tác.

### AutoFill — 자동 채우기

연속된 값, 날짜, 패턴, 수식 등을 Fill Handle로 복사하거나 확장한다.

예:
1, 2를 선택 후 drag → 3, 4, 5 ... 같은 계열 생성 가능.

수식을 drag할 때는 상대 참조가 이동한다는 점이 중요하다.

---

# 2. 셀 참조 — Cell Reference

## 2.1 상대 참조 — Relative Reference

A1처럼 $가 없는 참조다. 수식을 복사하면 상대 위치에 따라 주소가 바뀐다.

예:
C2 = A2 + B2  
C3로 복사하면 → A3 + B3

→ Relative reference phù hợp khi muốn cùng một logic chạy theo từng dòng.

---

## 2.2 절대 참조 — Absolute Reference

$A$1처럼 행과 열을 모두 고정한다.

예:
=B2*$F$1

수식을 아래로 복사해도 F1은 바뀌지 않는다.

→ Dùng khi có một hệ số cố định như thuế suất, tỷ lệ, đơn giá chuẩn.

---

## 2.3 혼합 참조 — Mixed Reference

- $A1 → 열 A 고정, 행 이동
- A$1 → 행 1 고정, 열 이동

혼합 참조는 가로·세로로 수식을 복사할 때 특히 중요하다.

### Mental model

$는 “바로 뒤에 있는 축을 잠근다”고 생각하면 쉽다.

- $A → column lock
- $1 → row lock

> **실기 핵심:** 계산작업에서 참조를 잘못 고정하면 함수 자체가 맞아도 여러 셀의 결과가 연쇄적으로 틀린다.

---

# 3. 수식과 연산자

## 3.1 주요 연산자

### 산술 연산자

- + 더하기
- - 빼기
- * 곱하기
- / 나누기
- ^ 거듭제곱
- % 백분율

### 비교 연산자

- =
- >
- <
- >=
- <=
- <> 같지 않음

### 문자열 연결

& 연산자로 문자열을 연결할 수 있다.

예:
=A1 & "님"

---

## 3.2 연산 우선순위

괄호가 가장 명확한 제어 수단이다.  
→ Khi biểu thức phức tạp, hãy dùng ngoặc để tránh phụ thuộc vào trí nhớ thứ tự toán tử.

예:
=A1+B1*C1  
은 곱셈이 먼저 수행된다.

=(A1+B1)*C1  
은 괄호 안이 먼저 수행된다.

시험에서는 결과 자체보다 “어떤 연산이 먼저 실행되는가”를 묻는 유형이 나올 수 있다.

---

# 4. 함수 — Function

## 4.1 함수의 구조

함수는 이름과 인수(argument)로 구성된다.

예:
=SUM(A1:A10)

- SUM → 함수 이름
- A1:A10 → argument/range

함수를 암기할 때는 문법보다 먼저 **질문을 함수로 번역하는 습관**을 만든다.

예:
“조건을 만족하는 값의 개수”  
→ COUNTIF 계열을 생각한다.

“조건에 따라 다른 결과”  
→ IF 계열을 생각한다.

“표에서 키를 찾아 대응값 반환”  
→ LOOKUP 계열을 생각한다.

---

## 4.2 기본 집계 함수

### SUM

합계를 구한다.

=SUM(B2:B10)

### AVERAGE

평균을 구한다.

=AVERAGE(B2:B10)

### MAX / MIN

최댓값과 최솟값을 구한다.

### COUNT / COUNTA

- COUNT: 숫자가 있는 셀의 개수
- COUNTA: 비어 있지 않은 셀의 개수

→ COUNT và COUNTA khác nhau ở loại dữ liệu được đếm.

---

## 4.3 조건 함수

### IF

조건이 TRUE인지 FALSE인지에 따라 다른 값을 반환한다.

형태:

=IF(조건, 참일 때 값, 거짓일 때 값)

예:
=IF(C2>=60,"합격","불합격")

### AND

모든 조건이 TRUE일 때 TRUE.

### OR

하나 이상의 조건이 TRUE면 TRUE.

### NOT

논리값을 반대로 바꾼다.

### Nested IF

여러 등급을 나눌 때 IF를 중첩할 수 있다.

다만 시험에서는 중첩 구조를 왼쪽에서 오른쪽으로 읽기보다 **조건 우선순위**를 먼저 적으면 실수를 줄일 수 있다.

---

## 4.4 조건부 집계 함수

### COUNTIF

한 조건을 만족하는 셀의 개수를 구한다.

### SUMIF

한 조건을 만족하는 데이터의 합계를 구한다.

### AVERAGEIF

한 조건을 만족하는 데이터의 평균을 구한다.

### COUNTIFS / SUMIFS / AVERAGEIFS

복수 조건을 처리한다.

→ IF류 함수의 핵심은 “조건 범위(criteria range)”와 “실제 계산 범위(sum/average range)”를 구분하는 것이다.

---

## 4.5 수학 함수

자주 연결되는 함수:

- ROUND: 지정 자릿수 반올림
- ROUNDUP: 올림
- ROUNDDOWN: 내림
- INT: 정수 부분 처리
- MOD: 나머지
- ABS: 절댓값
- SUM: 합계

### ROUND의 자리수

자리수 인수는 단순히 “소수 몇 자리”만 의미하지 않는다.

- 양수 → 소수점 아래 자리
- 0 → 정수 단위
- 음수 → 십, 백, 천 단위 등

예:
=ROUND(1234,-2) → 백 단위 반올림

---

## 4.6 통계 함수

- AVERAGE
- MAX / MIN
- COUNT / COUNTA
- RANK 계열
- LARGE / SMALL

### LARGE / SMALL

정렬 자체를 하지 않고도 k번째 큰 값 또는 작은 값을 찾는다.

예:
=LARGE(A1:A10,2)  
→ 두 번째로 큰 값

---

## 4.7 문자열 함수

### LEFT / RIGHT

문자열의 왼쪽/오른쪽에서 지정한 문자 수를 가져온다.

### MID

중간 위치에서 지정한 길이만큼 가져온다.

### LEN

문자열 길이를 구한다.

### FIND / SEARCH

문자열 안에서 특정 문자열의 위치를 찾는다.

### REPLACE / SUBSTITUTE

문자열 일부를 변경한다.

### UPPER / LOWER

영문 대소문자를 변환한다.

### CONCAT 또는 &

문자열을 결합한다.

> **판단법:** 문제에서 “앞 몇 글자”, “뒤 몇 글자”, “중간 몇 글자”가 보이면 LEFT / RIGHT / MID를 먼저 떠올린다.

---

## 4.8 날짜와 시간 함수

### TODAY

현재 날짜를 반환한다.

### NOW

현재 날짜와 시간을 반환한다.

### YEAR / MONTH / DAY

날짜에서 연, 월, 일을 분리한다.

### DATE

연·월·일을 조합하여 날짜 값을 만든다.

### WEEKDAY

요일을 숫자로 반환한다.

날짜 함수는 Excel이 날짜를 내부적으로 serial number로 다룬다는 점과 연결하면 이해가 쉬워진다.

---

## 4.9 찾기/참조 함수

### VLOOKUP

표의 첫 열에서 값을 찾아 같은 행의 다른 열 값을 반환한다.

Mental model:

**key를 왼쪽 첫 열에서 찾는다 → 같은 row의 n번째 column 값을 반환한다.**

### HLOOKUP

첫 행에서 값을 찾아 같은 열의 다른 행 값을 반환한다.

→ V = vertical, H = horizontal.

### INDEX / MATCH

직접적인 위치 기반 검색 구조를 만들 수 있다. 2급 범위에서는 LOOKUP류의 방향과 argument 구조를 읽는 능력이 중요하다.

### Exact vs Approximate match

근사 일치(approximate)는 데이터 정렬 조건 등 전제가 중요할 수 있다.  
→ Khi đề yêu cầu “정확히 같은 값”, exact match 조건을 확인해야 한다.

---

## 4.10 데이터베이스 함수

Database function은 표 형태 데이터에서 **field + criteria** 구조를 이용해 집계한다.

대표 예:

- DSUM
- DAVERAGE
- DCOUNT
- DMAX
- DMIN

### Criteria Range

조건 범위의 header가 원본 데이터의 field name과 연결되는 구조를 이해해야 한다.

→ Đây là phần rất quan trọng vì criteria range cũng xuất hiện trong Advanced Filter.

---

# 5. 오류 값 — Error Values

Excel 오류는 “망가졌다”가 아니라 원인을 알려주는 신호다.

| 오류 | 의미의 핵심 |
|---|---|
| #DIV/0! | 0으로 나눔 |
| #VALUE! | 잘못된 데이터 형식/인수 |
| #REF! | 잘못된 셀 참조 |
| #NAME? | 함수/이름 인식 실패 |
| #N/A | 찾는 값 없음 또는 사용할 수 없음 |
| ##### | 열 너비 부족 등 표시 문제 |

### 시험에서 중요한 구분

#####는 다른 오류와 달리 실제 계산 오류가 아니라 **표시 공간 부족**에서 자주 발생한다.

# 6. 데이터 입력과 서식

## 6.1 셀 서식 — Format Cells

서식은 값 자체보다 **표현 방식**을 바꾼다.

대표 영역:

- 표시 형식(Number)
- 맞춤(Alignment)
- 글꼴(Font)
- 테두리(Border)
- 채우기(Fill)
- 보호(Protection)

### 숫자와 표시 형식

같은 내부 값도 표시 형식에 따라 다르게 보일 수 있다.

예:
0.25  
→ 25%로 표시 가능

값과 표시가 다르다는 점이 중요하다.

---

## 6.2 사용자 지정 표시 형식

Custom number format은 값 자체를 바꾸지 않고 표시 규칙을 정의한다.

대표 구성:
양수 ; 음수 ; 0 ; 텍스트

→ Đây là khái niệm “presentation layer”: dữ liệu nội bộ giữ nguyên, chỉ cách hiển thị thay đổi.

---

## 6.3 조건부 서식 — Conditional Formatting

조건을 만족하는 셀에 자동으로 서식을 적용한다.

예:
- 80점 이상 강조
- 중복 값 표시
- 상위 값 표시

조건부 서식은 값을 변경하지 않는다.  
→ Nó thay cách nhìn, không thay dữ liệu gốc.

---

## 6.4 데이터 유효성 검사 — Data Validation

입력 가능한 값을 제한하거나 안내 메시지를 제공한다.

예:
- 1~100 사이 정수만 허용
- 목록에서 선택
- 특정 날짜 범위만 허용

→ Conditional Formatting은 “보여주는 규칙”, Data Validation은 “입력을 제한하는 규칙”이다.

---

# 7. 데이터 관리

## 7.1 정렬 — Sort

정렬은 행의 순서를 기준에 따라 바꾼다.

- 오름차순(Ascending)
- 내림차순(Descending)
- 다중 기준 정렬

예:
부서 오름차순 → 같은 부서 안에서 점수 내림차순.

→ Khi có nhiều tiêu chí, thứ tự level quyết định kết quả.

---

## 7.2 자동 필터 — AutoFilter

조건에 맞는 행만 화면에 표시한다. 데이터 자체를 삭제하지 않는다.

→ Filter = ẩn/hiện theo điều kiện, không xóa dòng.

대표 조건:
- 숫자 비교
- 텍스트 포함
- 날짜 조건
- 색 기준

---

## 7.3 고급 필터 — Advanced Filter

복잡한 criteria range를 사용하고, 결과를 다른 위치에 복사할 수 있다.

### 조건 범위의 핵심

- 같은 행의 조건 → AND
- 다른 행의 조건 → OR

이 논리는 실기에서 매우 중요하다.

예:

| 부서 | 점수 |
|---|---|
| 영업 | >=80 |

→ 부서가 영업 **AND** 점수가 80 이상.

조건을 다른 행에 쓰면 OR 관계가 된다.

---

## 7.4 부분합 — Subtotal

정렬된 데이터에서 그룹별 합계, 평균, 개수 등을 계산한다.

핵심 순서:

**그룹 기준으로 먼저 정렬 → 부분합 적용**

→ Nếu chưa sort đúng field nhóm, subtotal có thể tạo kết quả khó hiểu.

---

## 7.5 통합 — Consolidate

여러 범위의 데이터를 하나의 요약 결과로 합친다.

예:
여러 지점의 같은 형식 매출표 → 전체 지점 합계.

---

## 7.6 Goal Seek — 목표값 찾기

수식 결과를 원하는 값으로 만들기 위해 **하나의 입력값**을 역으로 찾는다.

예:
최종 이익을 1,000,000으로 만들려면 판매량이 얼마여야 하는가?

Mental model:

**목표 결과(Target) → 변경할 하나의 Input을 역산**

---

## 7.7 Data Table — 데이터 표

하나 또는 두 개의 입력값 변화에 따른 수식 결과를 표로 비교하는 What-if Analysis 도구다.

→ Dùng để xem nhiều scenario theo 1 hoặc 2 biến mà không cần tự viết lại nhiều công thức.

---

## 7.8 Scenario — 시나리오

여러 입력값 묶음을 시나리오로 저장하고 결과를 비교한다.

Goal Seek과 비교:

- Goal Seek → 원하는 결과에서 하나의 입력값을 역산
- Scenario → 여러 입력값 조합을 저장·비교

---

## 7.9 PivotTable — 피벗 테이블

피벗 테이블은 큰 목록형 데이터를 **행/열/값/필터** 축으로 재배치하여 빠르게 요약한다.

### 핵심 영역

- Rows
- Columns
- Values
- Filters

예:
원본: 날짜, 지점, 상품, 매출  
Pivot: 지점을 Row, 상품을 Column, 매출을 Sum으로 배치.

→ PivotTable không tạo dữ liệu mới; nó tạo một góc nhìn tổng hợp từ dữ liệu nguồn.

### PivotChart

PivotTable의 요약 구조를 chart로 시각화한다.

# 8. 차트 활용

## 8.1 차트의 목적

차트는 숫자를 예쁘게 꾸미는 것이 아니라 **비교, 추세, 구성비, 관계**를 빠르게 읽기 위한 도구다.

### 대표 선택 기준

- Column/Bar → 범주 간 크기 비교
- Line → 시간에 따른 추세
- Pie → 전체 대비 구성비
- Scatter → 두 연속형 변수 관계

시험에서는 차트 종류와 목적의 연결을 묻는 문제가 나온다.

---

## 8.2 차트 구성 요소

- Chart Area
- Plot Area
- Axis
- Axis Title
- Chart Title
- Legend
- Data Series
- Data Labels
- Gridlines

### Series와 Category

Data Series는 비교할 값의 묶음이고 Category는 그 값을 나누는 범주다.

행/열 전환을 하면 series와 category 해석이 달라질 수 있다.

# 10. 매크로 활용

## 10.1 Macro란 무엇인가

Macro는 반복 작업을 자동화하기 위해 일련의 동작을 기록하거나 코드로 정의한 것이다.

→ Macro = automation of repeated actions.

### Record Macro

사용자의 작업을 기록하여 VBA procedure 형태로 저장할 수 있다.

### 실행

버튼, 단축키, macro dialog 등을 통해 실행할 수 있다.

### 보안

Macro에는 코드가 포함될 수 있으므로 출처가 불분명한 파일의 macro를 무조건 활성화하면 안 된다.

# 11. 필기에서 자주 헷갈리는 비교

| A | B | 핵심 차이 |
|---|---|---|
| Workbook | Worksheet | 파일 전체 vs 파일 안의 시트 |
| Value | Format | 실제 데이터 vs 표시 방식 |
| Relative | Absolute | 복사 시 이동 vs 고정 |
| COUNT | COUNTA | 숫자 개수 vs 비어 있지 않은 셀 개수 |
| IF | AND/OR | 조건 분기 vs 여러 조건의 논리 결합 |
| Sort | Filter | 행 순서 변경 vs 조건 행만 표시 |
| AutoFilter | Advanced Filter | 간단한 UI 조건 vs criteria range 기반 복합 조건 |
| Conditional Formatting | Data Validation | 보이는 서식 변경 vs 입력 제한 |
| Goal Seek | Scenario | 하나의 입력값 역산 vs 여러 입력 조합 비교 |
| PivotTable | 일반 표 | 동적 요약 구조 vs 원본 데이터 배치 |
| Chart | PivotChart | 일반 범위 기반 vs Pivot 구조와 연동 |
| Macro | Formula | 작업 자동화 vs 셀 계산 |

# 13. 함수 선택 decision tree

문제 문장을 읽고 아래처럼 번역한다.

1. **단순 합계/평균/개수인가?**  
   → SUM / AVERAGE / COUNT

2. **조건이 있는가?**  
   → IF 또는 COUNTIF/SUMIF/AVERAGEIF 계열

3. **문자열 일부를 잘라야 하는가?**  
   → LEFT / RIGHT / MID

4. **날짜에서 연·월·일을 추출하는가?**  
   → YEAR / MONTH / DAY

5. **표에서 key로 대응값을 찾는가?**  
   → VLOOKUP / HLOOKUP 등

6. **목록 + field + criteria 구조인가?**  
   → Database function

이 decision tree는 필기와 실기 모두에서 함수 이름을 무작정 암기하는 것보다 강하다.
