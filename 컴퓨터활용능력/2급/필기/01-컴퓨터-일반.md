# 01 — 컴퓨터 일반

> **Baseline:** 컴퓨터활용능력 2급 필기 · 2024–2026 출제기준 · Windows 10 기준  
> **학습 언어:** 한국어 핵심 문장 → tiếng Việt giải thích → English keyword khi cần  
> **목표:** 단순 암기보다 “컴퓨터가 데이터를 어떻게 입력·처리·저장·전송·보호하는가”라는 하나의 mental model로 문제를 연결한다.

## 0. 이 과목을 어떻게 읽을 것인가

컴퓨터 일반은 Windows 메뉴 이름을 외우는 과목처럼 보이지만, 실제로는 **컴퓨터 시스템의 구성 → 운영체제의 역할 → 네트워크를 통한 연결 → 정보 보호**라는 한 흐름으로 읽는 것이 가장 안정적이다.  
→ Môn 컴퓨터 일반 trông giống một tập hợp kiến thức rời như Windows, phần cứng, Internet và bảo mật, nhưng chúng thực chất nối thành một chuỗi: máy tính xử lý dữ liệu thế nào → hệ điều hành quản lý tài nguyên ra sao → máy tính giao tiếp qua mạng thế nào → dữ liệu được bảo vệ ra sao.

시험에서는 정의를 그대로 묻기도 하지만, 더 자주 나오는 것은 “A와 B 중 어느 설명이 맞는가”, “어떤 장치가 더 빠른가”, “어떤 프로토콜이 어떤 목적을 가지는가” 같은 **비교형 판단**이다.  
→ Khi làm đề, hãy ưu tiên học theo cặp đối chiếu như RAM ↔ ROM, HDD ↔ SSD, LAN ↔ WAN, HTTP ↔ HTTPS, 대칭키 ↔ 공개키, 바이러스 ↔ 웜. Điểm quan trọng là biết chúng khác nhau theo tiêu chí nào.

# 1. 컴퓨터 시스템 활용

## 1.1 컴퓨터의 전체 구조: 입력 → 처리 → 저장 → 출력

컴퓨터는 데이터를 **입력(Input)** 받아 CPU가 **처리(Process)** 하고, 필요하면 기억장치에 **저장(Storage)** 한 뒤 결과를 **출력(Output)** 하는 시스템이다.  
→ Hãy luôn hình dung máy tính như một pipeline: nhập dữ liệu → CPU xử lý → bộ nhớ/lưu trữ giữ dữ liệu → thiết bị đầu ra đưa kết quả cho người dùng.

이 구조를 이해하면 CPU, RAM, SSD, 키보드, 모니터가 서로 다른 장치이지만 왜 하나의 시스템으로 묶이는지 자연스럽게 설명할 수 있다.

| 역할 | 한국어 | English | 대표 예 |
|---|---|---|---|
| 입력 | 입력장치 | Input device | 키보드, 마우스, 스캐너 |
| 처리 | 중앙처리장치 | CPU | ALU, Control Unit, Register |
| 기억 | 기억장치 | Memory / Storage | Register, Cache, RAM, SSD |
| 출력 | 출력장치 | Output device | 모니터, 프린터, 스피커 |

### 시험 포인트

- CPU는 저장장치가 아니라 처리의 중심이다.
- RAM은 주기억장치이고 SSD/HDD는 보조기억장치다.
- 입출력 장치는 CPU와 사용자 또는 외부 세계 사이의 경계에 있다.

> **연결:** 이 전체 구조에서 “누가 자원을 배분하고 프로그램 실행을 관리하는가?”라는 질문이 생기며, 그 답이 운영체제다.

## 1.2 운영체제 — Operating System

운영체제(OS)는 사용자와 하드웨어 사이에서 CPU, 메모리, 파일, 장치와 프로세스를 관리하는 시스템 소프트웨어다.  
→ Hệ điều hành không chỉ là giao diện Windows. Nó là lớp trung gian quản lý tài nguyên phần cứng và tạo môi trường để ứng dụng chạy.

### 운영체제의 핵심 기능

1. **프로세스 관리 (Process Management)**  
   실행 중인 프로그램에 CPU 시간을 배분한다.  
   → Quản lý tiến trình và chia thời gian CPU.

2. **기억장치 관리 (Memory Management)**  
   프로그램이 사용할 메모리 영역을 할당하고 회수한다.  
   → Cấp phát và thu hồi RAM.

3. **파일 시스템 관리 (File System Management)**  
   파일과 폴더를 저장·검색·보호한다.  
   → Quản lý file, thư mục và quyền truy cập.

4. **장치 관리 (Device Management)**  
   프린터, 키보드, 디스크 같은 장치를 드라이버를 통해 제어한다.  
   → Điều khiển thiết bị thông qua driver.

5. **사용자 인터페이스 제공 (User Interface)**  
   GUI 또는 CLI를 통해 사용자가 시스템을 조작할 수 있게 한다.

### GUI와 CLI

**GUI(Graphical User Interface)** 는 아이콘, 창, 메뉴를 이용하고, **CLI(Command Line Interface)** 는 명령어 문자열을 입력한다.  
→ GUI dễ dùng hơn cho người mới; CLI thường mạnh hơn cho quản trị hoặc thao tác lặp lại.

시험에서는 “GUI이므로 반드시 마우스만 사용한다”처럼 지나치게 절대적인 문장을 의심해야 한다. 키보드 단축키도 GUI 환경에서 사용된다.

## 1.3 Windows 10 기본 요소

2024–2026 필기에서 운영체제는 Windows 10 기준이다. 메뉴의 세부 위치보다 각 요소의 **역할**을 이해하는 것이 중요하다.

### 바탕 화면 — Desktop

바탕 화면은 Windows 로그인 후 보이는 기본 작업 공간이다. 아이콘, 바로 가기, 휴지통 등이 배치될 수 있다.  
→ Desktop là không gian làm việc chính, không phải nơi dữ liệu bắt buộc phải được lưu.

### 시작 메뉴 — Start Menu

시작 메뉴는 앱 실행, 검색, 설정, 전원 기능으로 연결되는 중심 진입점이다.

### 작업 표시줄 — Taskbar

작업 표시줄은 실행 중인 앱과 고정된 앱을 확인·전환하고 알림 영역을 통해 시스템 상태를 확인하는 공간이다.

### 바로 가기 — Shortcut

바로 가기는 원본 파일이나 프로그램을 가리키는 링크다. 바로 가기를 삭제해도 일반적으로 원본 자체는 삭제되지 않는다.  
→ Đây là bẫy rất hay gặp: xóa shortcut không đồng nghĩa xóa file gốc.

### 휴지통 — Recycle Bin

일반적으로 로컬 디스크에서 삭제한 파일은 휴지통으로 이동하여 복원할 수 있다. 하지만 모든 삭제가 반드시 휴지통을 거치는 것은 아니다.  
→ Shift+Delete hoặc một số loại vị trí/thiết bị có thể bỏ qua Recycle Bin.

## 1.4 파일과 폴더

파일(File)은 데이터를 하나의 단위로 저장한 것이고, 폴더(Folder)는 파일과 다른 폴더를 논리적으로 묶는 컨테이너다.

### 파일 이름과 확장자

확장자(extension)는 파일 형식이나 연결 프로그램을 판단하는 데 사용된다.

| 확장자 | 의미 |
|---|---|
| .txt | 텍스트 |
| .jpg / .png | 이미지 |
| .mp3 | 오디오 |
| .mp4 | 비디오 |
| .xlsx | Excel 통합 문서 |
| .exe | 실행 파일 |
| .zip | 압축 파일 |

확장자를 단순히 바꾼다고 내부 파일 형식이 변환되는 것은 아니다.  
→ Đổi tên đuôi file không tự động chuyển đổi cấu trúc dữ liệu bên trong.

### 경로 — Path

경로는 파일이 파일 시스템 어디에 있는지 나타낸다.

- 절대 경로(Absolute Path): 루트부터 전체 위치를 지정
- 상대 경로(Relative Path): 현재 위치를 기준으로 지정

### 파일 속성

대표적인 속성에는 읽기 전용(Read-only), 숨김(Hidden) 등이 있다.  
→ Thuộc tính file ảnh hưởng cách file được hiển thị hoặc chỉnh sửa, nhưng không đồng nghĩa với mã hóa hay bảo mật tuyệt đối.

## 1.5 Windows 설정과 시스템 관리

Windows 설정 문제는 메뉴 이름 자체보다 “어떤 종류의 설정인가”를 분류하면 쉽다.

### 장치 — Devices

마우스, 키보드, 프린터, Bluetooth 등 주변장치와 관련된다.

### 네트워크 및 인터넷 — Network & Internet

Wi-Fi, Ethernet, VPN, 네트워크 상태 및 연결 설정을 다룬다.

### 앱 — Apps

설치된 응용 프로그램 관리, 기본 앱 연결 등이 중심이다.

### 계정 — Accounts

사용자 계정, 로그인 옵션, 동기화 설정 등이 관련된다.

### 시간 및 언어 — Time & Language

날짜, 시간, 지역, 언어, 키보드 입력 체계 등을 관리한다.

### 접근성 — Accessibility

시각·청각·입력 지원 등 사용 편의 기능을 제공한다.

### 업데이트 및 보안 — Update & Security

Windows Update, 복구, 보안 기능과 연관된다.

> **시험 판단법:** “프린터 설정”을 개인정보 메뉴에서 찾는 식으로 범주가 어긋난 설명은 오답일 가능성이 높다.

## 1.6 CPU — Central Processing Unit

CPU는 명령어를 해석하고 연산을 수행하며 시스템 동작을 제어하는 핵심 장치다.

### ALU — Arithmetic Logic Unit

덧셈·뺄셈 같은 산술 연산과 AND, OR, 비교 같은 논리 연산을 수행한다.

### Control Unit — 제어장치

명령어를 해석하고 각 장치에 제어 신호를 보낸다.

### Register — 레지스터

CPU 내부의 초고속 소형 기억장치다. 현재 처리 중인 명령어나 데이터를 임시 보관한다.  
→ Register rất nhỏ nhưng rất nhanh vì nằm ngay trong CPU.

### CPU 성능 관련 개념

- Clock: 동작 주기의 기준
- Core: 독립적으로 명령을 처리할 수 있는 처리 단위
- Cache: CPU와 RAM 사이 속도 차이를 완화하는 고속 메모리

클럭이 높다고 무조건 실제 프로그램 성능이 비례해서 높아지는 것은 아니다. 코어 수, 아키텍처, 캐시, 메모리 등도 영향을 준다.

## 1.7 기억장치 계층 — Memory Hierarchy

기억장치는 보통 **빠를수록 작고 비싸며**, **느릴수록 크고 저렴하다**는 trade-off를 가진다.

일반적인 속도 순서는 다음과 같이 이해하면 된다.

**Register → Cache → RAM → SSD → HDD**

→ Trong đề thi, hãy giữ quy luật: càng gần CPU thì thường càng nhanh nhưng dung lượng nhỏ hơn.

### RAM — Random Access Memory

RAM은 실행 중인 프로그램과 데이터를 저장하는 주기억장치이며, 일반적으로 전원이 꺼지면 내용이 사라지는 휘발성(volatile) 메모리다.

### ROM — Read Only Memory

ROM은 전원이 꺼져도 내용이 유지되는 비휘발성(non-volatile) 메모리 계열이다. 펌웨어 저장 등에 사용된다.

### Cache Memory

캐시는 CPU가 자주 사용하는 데이터의 복사본을 가까이에 두어 RAM 접근 지연을 줄인다.

### HDD와 SSD

HDD는 자기 디스크와 기계적 구조를 사용하며, SSD는 플래시 메모리를 사용한다. 일반적으로 SSD가 접근 속도, 충격 저항, 소음 측면에서 유리하다.

| 기준 | HDD | SSD |
|---|---|---|
| 구조 | 자기 디스크/기계식 | 반도체 플래시 |
| 속도 | 상대적으로 느림 | 상대적으로 빠름 |
| 소음 | 발생 가능 | 거의 없음 |
| 충격 | 상대적으로 취약 | 상대적으로 강함 |
| 가격/용량 | 대용량 단가 유리 | 보통 더 비쌈 |

## 1.8 데이터 표현: bit, byte, 진수

### bit와 byte

bit는 0 또는 1을 표현하는 최소 단위다.  
**1 byte = 8 bits**

### 2진수와 16진수

컴퓨터 내부는 2진수(Binary)를 사용한다. 16진수(Hexadecimal)는 긴 이진 패턴을 사람이 짧게 읽기 위해 자주 사용한다.

- Binary: 0, 1
- Decimal: 0–9
- Hexadecimal: 0–9, A–F

예: 1111₂ = 15₁₀ = F₁₆

### 문자 코드

ASCII는 초기 영문 중심 문자 코드이고, Unicode는 여러 언어 문자를 통합적으로 표현하기 위한 문자 체계다.  
→ Unicode giúp biểu diễn tiếng Hàn, tiếng Việt và nhiều hệ chữ trong một chuẩn chung.

## 1.9 소프트웨어 분류

소프트웨어는 크게 **시스템 소프트웨어(System Software)** 와 **응용 소프트웨어(Application Software)** 로 나눌 수 있다.

### 시스템 소프트웨어

운영체제, 장치 드라이버, 일부 유틸리티처럼 컴퓨터 시스템 자체 운영을 지원한다.

### 응용 소프트웨어

Word, Excel, 브라우저, 그래픽 프로그램처럼 사용자의 특정 작업을 수행한다.

### 유틸리티 — Utility

백업, 압축, 보안 검사, 디스크 관리 등 시스템 유지·보조 작업을 수행한다.

> **핵심 구분:** 운영체제는 컴퓨터를 운영하고, 응용 프로그램은 사용자의 업무를 수행한다.

# 2. 인터넷 자료 활용

## 2.1 네트워크 기본 개념

네트워크(Network)는 여러 컴퓨터와 장치를 연결하여 데이터와 자원을 공유하는 구조다.

### LAN과 WAN

- **LAN(Local Area Network)**: 건물, 사무실 등 비교적 좁은 범위
- **WAN(Wide Area Network)**: 도시·국가처럼 넓은 범위를 연결

Internet은 전 세계의 다양한 네트워크가 상호 연결된 거대한 network of networks다.

### 서버와 클라이언트

Server는 서비스를 제공하고 Client는 서비스를 요청한다.  
→ Khi browser yêu cầu một web page, browser đóng vai client; web server trả nội dung.

이 구분은 절대적인 장치 종류가 아니라 **역할(role)** 이다. 한 컴퓨터가 상황에 따라 서버이자 클라이언트가 될 수 있다.

---

## 2.2 TCP/IP와 주소

Internet 통신은 여러 프로토콜 계층이 협력해 동작한다. 2급에서는 각 프로토콜의 역할을 구분하는 것이 중요하다.

### IP Address

IP 주소는 네트워크에서 장치를 식별하고 패킷을 전달하기 위한 논리 주소다.

- IPv4: 32-bit
- IPv6: 128-bit

IPv6는 IPv4 주소 고갈 문제를 완화하고 더 큰 주소 공간을 제공한다.

### Domain Name과 DNS

도메인 이름은 사람이 기억하기 쉬운 이름이고, DNS(Domain Name System)는 도메인 이름을 IP 주소와 연결해 준다.  
→ DNS giống danh bạ chuyển tên miền thành địa chỉ IP.

### URL

URL(Uniform Resource Locator)은 네트워크 자원의 위치와 접근 방법을 나타낸다.

주요 구성 요소는 scheme/protocol, host/domain, path로 나눠 생각하면 된다.

---

## 2.3 주요 인터넷 프로토콜

| 프로토콜 | 역할 | 기억 포인트 |
|---|---|---|
| HTTP | 웹 문서 전송 | 기본 Web |
| HTTPS | 암호화된 HTTP | TLS 기반 보안 |
| FTP | 파일 전송 | File Transfer |
| SMTP | 메일 발송 | Send |
| POP3 | 메일 다운로드 중심 | 서버에서 가져오기 |
| IMAP | 서버 동기화 중심 | 여러 기기 사용에 유리 |
| DNS | 이름 ↔ IP 해석 | Domain resolution |

### SMTP vs POP3/IMAP

SMTP는 주로 **보내기**, POP3와 IMAP은 **받기/관리**와 관련된다.  
→ Đây là cặp rất hay xuất hiện trong câu hỏi so sánh.

### HTTP vs HTTPS

HTTPS는 HTTP 통신에 암호화와 서버 인증 등의 보안 계층을 더한다.  
→ HTTPS giúp bảo vệ dữ liệu khi truyền, nhưng không có nghĩa mọi nội dung của website đều đáng tin tuyệt đối.

## 2.4 웹 브라우저 공통 기능

2024–2026 기준에서 브라우저는 특정 버전보다 공통 기능을 이해하는 것이 중요하다.

대표 기능:

- 주소 입력과 웹 페이지 이동
- 탭(tab)
- 즐겨찾기/북마크(bookmark)
- 방문 기록(history)
- 다운로드(download)
- 캐시(cache)
- 쿠키(cookie)
- 개인정보/보안 설정

### Cache와 Cookie

**Cache** 는 이미지나 문서 같은 자원의 사본을 저장하여 재방문 시 로딩을 빠르게 한다.  
**Cookie** 는 사이트가 브라우저에 저장하는 작은 상태 정보로 로그인 상태, 사용자 설정 등에 활용될 수 있다.

→ Cache = tối ưu tải tài nguyên; Cookie = lưu trạng thái. Không nên đồng nhất hai khái niệm.

## 2.5 전자우편 — E-mail

전자우편은 메시지를 네트워크를 통해 주고받는 서비스다.

### 주요 필드

- To: 기본 수신자
- Cc(Carbon Copy): 참조 수신자, 다른 수신자에게 보임
- Bcc(Blind Carbon Copy): 숨은 참조, 다른 수신자가 주소를 볼 수 없음

### 스팸과 피싱

Spam은 원하지 않는 대량 메시지이고, Phishing은 신뢰할 수 있는 기관을 사칭하여 계정·금융 정보를 탈취하려는 공격이다.

# 3. 멀티미디어 활용

## 3.1 Bitmap과 Vector

### Bitmap / Raster

픽셀(pixel) 격자로 이미지를 표현한다. 사진 표현에 적합하지만 크게 확대하면 픽셀이 보이고 품질이 저하될 수 있다.

대표 형식: JPEG, PNG, GIF, BMP

### Vector

선, 곡선, 도형을 수학적 정보로 표현한다. 확대·축소에 상대적으로 강하고 로고, 아이콘, 도형에 적합하다.

→ Bitmap = ảnh theo pixel; Vector = hình theo mô tả toán học.

---

## 3.2 대표 이미지 형식

### JPEG

사진처럼 색 변화가 많은 이미지에 적합하며 일반적으로 손실 압축(lossy compression)을 사용한다.

### PNG

무손실 압축(lossless compression)을 사용하고 투명도(alpha)를 지원할 수 있다.

### GIF

제한된 색상 수를 사용하며 간단한 animation을 지원한다.

시험에서는 “JPEG는 무손실 압축만 사용한다” 같은 문장을 구분해야 한다.

---

## 3.3 오디오와 비디오

디지털 오디오는 아날로그 음파를 일정 간격으로 측정하는 sampling 과정을 통해 표현된다.

- Sampling rate가 높을수록 더 자주 측정
- Bit depth가 높을수록 한 번의 측정을 더 세밀하게 표현

비디오는 연속된 frame과 audio를 결합하며 codec을 통해 압축할 수 있다.

### Codec vs Container

Codec은 encode/decode 방식이고, container는 여러 stream을 묶는 파일 구조다.  
→ Một file video có thể dùng container và codec khác nhau; hai khái niệm không đồng nhất.

# 4. 최신 정보통신기술 활용

## 4.1 Cloud Computing

Cloud computing은 인터넷을 통해 서버, 저장공간, 소프트웨어 같은 컴퓨팅 자원을 필요에 따라 사용하는 모델이다.

### 대표 서비스 모델

- IaaS: Infrastructure as a Service
- PaaS: Platform as a Service
- SaaS: Software as a Service

2급에서는 이름 암기보다 범위를 이해하면 된다.

**IaaS → 더 낮은 인프라 수준**, **SaaS → 완성된 애플리케이션 사용**이라는 축으로 기억한다.

---

## 4.2 IoT — Internet of Things

IoT는 센서와 네트워크를 이용해 사물의 상태를 수집하고 다른 시스템과 데이터를 교환하는 구조다.

대표 흐름:

**센서 → 네트워크 → 서버/클라우드 → 분석 → 제어**

→ Smart home, smart factory, wearable device đều có thể được hiểu theo luồng này.

---

## 4.3 모바일·무선 통신

Wi-Fi는 근거리 무선 네트워크 접속에 널리 사용되고, Bluetooth는 비교적 가까운 거리에서 주변기기 연결에 자주 사용된다.

NFC는 매우 짧은 거리에서 통신하는 기술로 결제, 태그 인식 등에 사용된다.

시험에서는 무선 기술들을 “모두 같은 거리·속도·목적”이라고 보지 말고 사용 범위와 목적을 구분해야 한다.

# 5. 컴퓨터 시스템 보호

## 5.1 정보보안의 세 목표 — CIA Triad

정보보안의 가장 중요한 mental model은 **기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)** 이다.

### 기밀성 — Confidentiality

허가된 사람만 정보를 볼 수 있어야 한다.  
→ Không để người không có quyền đọc dữ liệu.

### 무결성 — Integrity

정보가 허가 없이 변경·삭제되지 않아야 한다.  
→ Bảo đảm dữ liệu không bị sửa trái phép.

### 가용성 — Availability

필요할 때 시스템과 정보에 접근할 수 있어야 한다.  
→ Dịch vụ phải sẵn sàng khi cần.

---

## 5.2 인증과 권한

**인증(Authentication)** 은 “당신이 누구인가?”를 확인하고, **인가/권한 부여(Authorization)** 는 “무엇을 할 수 있는가?”를 결정한다.

→ Authentication = xác minh danh tính. Authorization = quyết định quyền sau khi biết danh tính.

비밀번호, OTP, 생체정보 등 여러 요소를 조합하면 다중요소인증(MFA)을 구성할 수 있다.

---

## 5.3 암호화, 해시, 전자서명

### 대칭키 암호화 — Symmetric Encryption

암호화와 복호화에 같은 비밀키를 사용한다. 일반적으로 빠르지만 키를 안전하게 공유해야 하는 문제가 있다.

### 공개키 암호화 — Asymmetric/Public-key Encryption

공개키와 개인키의 쌍을 사용한다. 키 교환, 인증, 전자서명 등에 활용된다.

### Hash

Hash function은 입력 데이터를 고정 길이의 digest로 변환한다. 일반적인 보안 hash는 원문 복원이 목적이 아니다.

### Digital Signature

전자서명은 발신자 확인과 데이터 무결성 검증에 사용된다. 일반적으로 개인키로 서명하고 공개키로 검증하는 구조를 이해하면 된다.

> **오답 방지:** Hash를 “암호화 후 다시 복호화하는 기술”로 보면 안 된다.

---

## 5.4 악성코드 — Malware

### Virus

다른 파일이나 프로그램에 붙어 실행되며 전파되는 형태가 대표적이다.

### Worm

독립적으로 네트워크를 통해 자기 복제·전파할 수 있다.

### Trojan Horse

정상 프로그램처럼 위장하여 사용자가 실행하도록 유도한다.

### Ransomware

파일을 암호화하거나 시스템 사용을 제한하고 금전을 요구한다.

### Spyware

사용자 정보나 활동을 몰래 수집한다.

| 유형 | 핵심 특징 |
|---|---|
| Virus | 다른 파일/프로그램에 기생 |
| Worm | 자기 복제·네트워크 전파 |
| Trojan | 정상 프로그램으로 위장 |
| Ransomware | 사용 불가 상태를 만들고 금전 요구 |
| Spyware | 정보 몰래 수집 |

---

## 5.5 Firewall, Update, Backup

### Firewall — 방화벽

네트워크 트래픽을 규칙에 따라 허용하거나 차단하여 내부 시스템을 보호한다.  
→ Firewall không phải antivirus; nó kiểm soát lưu lượng mạng.

### Security Update

취약점이 발견되면 보안 업데이트를 적용하여 공격 가능성을 줄인다.

### Backup

백업은 원본 데이터 손실에 대비해 별도의 복사본을 유지하는 것이다.

대표적인 3-2-1 원칙은 복사본 3개, 서로 다른 매체 2종, 분리된 복사본 1개라는 사고방식이다.  
→ Backup là cơ chế tăng khả năng phục hồi, không thay thế phòng chống malware.

# 6. 자주 헷갈리는 비교 정리

| A | B | 결정적 차이 |
|---|---|---|
| RAM | ROM | RAM은 일반적으로 휘발성, ROM은 비휘발성 |
| Cache | RAM | Cache가 CPU에 더 가깝고 빠름 |
| HDD | SSD | 자기/기계식 vs 플래시 반도체 |
| Shortcut 삭제 | 원본 삭제 | Shortcut 삭제는 보통 원본 삭제가 아님 |
| LAN | WAN | 좁은 범위 vs 넓은 범위 |
| IP | Domain | 네트워크 주소 vs 사람이 읽기 쉬운 이름 |
| DNS | DHCP | 이름 해석 vs IP 설정 자동 할당 |
| SMTP | POP3/IMAP | 메일 보내기 vs 메일 받기/동기화 |
| Cache | Cookie | 자원 사본 vs 사이트 상태 정보 |
| Authentication | Authorization | 누구인가 vs 무엇을 할 수 있는가 |
| Encryption | Hash | 복호화 가능한 암호 체계 vs 일방향 digest 목적 |
| Virus | Worm | 숙주 파일 기생 vs 독립 자기전파 |
| Bitmap | Vector | 픽셀 기반 vs 수학적 도형 기반 |

# 7. 문제를 푸는 판단 규칙

## 7.1 “항상”, “절대”, “무조건”을 경계한다

컴퓨터 개념에는 조건이 붙는 경우가 많다.  
예: “삭제한 모든 파일은 반드시 휴지통으로 간다”는 설명은 Shift+Delete 같은 예외 때문에 틀릴 수 있다.

## 7.2 목적을 먼저 찾는다

기술 이름을 모를 때는 “이 기술이 해결하려는 문제가 무엇인가?”를 본다.

- DNS → 사람이 IP를 외우기 어려움
- Cache → 느린 접근을 줄임
- Firewall → 불필요한 네트워크 접근 통제
- Backup → 데이터 손실 후 복구

## 7.3 계층을 섞지 않는다

- CPU는 처리
- RAM은 실행 중 데이터 보관
- SSD는 장기 저장
- OS는 자원 관리
- App은 사용자의 업무 수행

서로 다른 계층을 섞은 설명이 오답으로 자주 나온다.
