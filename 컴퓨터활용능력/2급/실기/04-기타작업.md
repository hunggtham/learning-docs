# 04 — 기타작업

> **목표:** 데이터를 올바른 chart로 표현하고, 반복 작업을 macro로 자동화한다.  
> **핵심 원칙:** Chart는 “예쁘게 꾸미기”가 아니라 **데이터 관계를 정확히 표현**하는 작업이고, Macro는 “코딩 시험”이 아니라 **지시된 동작을 재현 가능한 절차로 기록**하는 작업이다.

# 1. 차트 작성

## 1.1 먼저 질문을 읽는다

Chart를 만들기 전에 무엇을 보여주려는지 판단한다.

- 범주별 크기 비교 → Column/Bar
- 시간 추세 → Line
- 전체 대비 구성비 → Pie
- 두 수치 변수 관계 → Scatter

실기에서는 문제에서 chart type이 지정되는 경우 그 지시를 그대로 따른다.

---

# 2. Source Range

차트의 가장 첫 단계는 올바른 data range를 선택하는 것이다.

확인:

- Header 포함 여부
- 불필요한 total row 포함 여부
- Category label이 맞는지
- Series data가 맞는지

→ Chart sai rất nhiều khi chọn nhầm source range chứ không phải vì thao tác format.

---

# 3. Series와 Category

예:

| 월 | 서울 | 부산 |
|---|---:|---:|
| 1월 | 100 | 80 |
| 2월 | 120 | 90 |

가능한 해석:

- Category = 월
- Series = 서울, 부산

행/열 전환(Switch Row/Column)을 하면 해석이 바뀔 수 있다.

### 실전 판단

문제에서 “서울과 부산의 월별 매출 비교”라면 보통 서울/부산이 series이고 월이 category가 된다.

---

# 4. Chart Elements

자주 조정하는 요소:

- Chart Title
- Axis Title
- Legend
- Data Labels
- Gridlines
- Data Series
- Plot Area
- Chart Area

## 4.1 Title

문제에서 지정한 문구를 정확히 입력한다.

## 4.2 Legend

위치가 지정되면 Top/Bottom/Left/Right를 정확히 맞춘다.

## 4.3 Data Labels

값, category name, percentage 등 표시 항목을 구분한다.

## 4.4 Axis

최소/최대값, major unit, number format 등 axis option이 지정될 수 있다.

---

# 5. Chart Type과 Combo

하나의 chart에서 series별로 다른 type을 사용할 수 있는 경우가 있다.

예:
매출 → Column  
성장률 → Line + Secondary Axis

하지만 문제에서 요구하지 않으면 임의로 변경하지 않는다.

→ Trong thi, “đúng yêu cầu” quan trọng hơn “trình bày đẹp theo ý mình”.

---

# 6. Chart Format

주요 서식:

- Fill
- Border
- Font
- Series color/style
- Marker
- Number format

### 원칙

문제에서 요구한 property만 변경하고, 불필요한 design change를 최소화한다.

---

# 7. 차트 검증 checklist

1. Chart type이 맞는가?
2. Source range가 맞는가?
3. Series와 category가 뒤바뀌지 않았는가?
4. Title text가 정확한가?
5. Legend 위치가 맞는가?
6. Data label이 필요한가?
7. Axis option이 지정값과 같은가?
8. Chart 위치/크기가 요구와 맞는가?

---

# 8. 매크로 — Macro

Macro는 반복되는 Excel 작업을 기록하거나 VBA code로 정의하여 다시 실행하는 자동화 기능이다.

2급 실기에서는 먼저 **Record Macro → 지정된 작업 수행 → Stop Recording → 실행 확인** 흐름을 확실히 익힌다.

---

# 9. Record Macro workflow

## Step 1 — 기록 시작

View 또는 Developer 관련 macro menu에서 Record Macro를 시작한다.

## Step 2 — 이름 확인

Macro name에는 규칙이 있으므로 문제에서 이름을 지정하면 정확히 따른다.

## Step 3 — 작업 수행

문제에서 요구한 동작만 수행한다.

예:
특정 범위 글꼴/색/정렬 변경.

## Step 4 — 기록 종료

Stop Recording.

## Step 5 — 실행 검증

다른 조건에서 macro를 실행해 예상 동작이 재현되는지 본다.

---

# 10. Macro의 상대/절대 동작

Macro recorder는 사용자의 실제 동작을 기록하므로, 어떤 cell을 기준으로 동작을 기록했는지가 중요하다.

Relative Reference mode를 사용하는 상황과 일반 absolute recording을 구분해야 한다.

→ Điều này giống tư duy cell reference: macro có thể gắn với vị trí cụ thể hoặc thao tác tương đối tùy cách ghi.

---

# 11. Macro 실행

Macro는 여러 방법으로 실행할 수 있다.

- Macro dialog
- Shortcut
- Button/Control 연결

문제에서 button 또는 control에 macro를 연결하도록 요구하면 단순히 macro를 만들어 놓는 것만으로는 끝나지 않는다.

---

# 12. Macro 보안

Macro는 code를 실행할 수 있으므로 출처가 불분명한 workbook의 macro를 무조건 활성화해서는 안 된다.

시험에서는 제공된 환경과 지시 범위 안에서 사용하지만, 실제 업무에서는 security boundary를 이해해야 한다.

---

# 13. Macro에서 자주 발생하는 실수

| 실수 | 원인 | 방지 |
|---|---|---|
| Macro 이름 오류 | 지시문 대충 읽음 | 기록 전 이름부터 확인 |
| 불필요한 클릭까지 기록 | 작업 순서 미정 | 시작 전 동작을 mental rehearsal |
| Stop Recording 누락 | 기록 상태 인식 실패 | 작업 직후 반드시 종료 |
| 잘못된 cell 기준 | recording 위치 오류 | 시작 cell 확인 |
| Button 연결 누락 | macro 생성만 하고 종료 | 마지막에 Assign Macro 검증 |
| 저장 형식 문제 | macro 포함 workbook 특성 미인지 | 시험 지시의 file format 유지 |

---

# 14. Chart와 Macro를 연결해서 이해하기

Chart는 data를 사람이 빠르게 이해하도록 **output representation**을 바꾸고, Macro는 반복 UI operation을 **automation procedure**로 바꾼다.

즉:

- Formula → 계산 자동화
- PivotTable → 요약 자동화
- Chart → 시각 해석
- Macro → 작업 절차 자동화

이렇게 연결하면 기타작업이 별도의 잡다한 기능 모음으로 보이지 않는다.
