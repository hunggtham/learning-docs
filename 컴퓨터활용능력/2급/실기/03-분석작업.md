# 03 — 분석작업

> **목표:** 개별 셀 계산을 넘어 표 전체를 재구성하고 요약하며, 입력값 변화가 결과에 어떤 영향을 주는지 분석한다.  
> **핵심 질문:** “이 문제는 데이터를 정리하는가, 요약하는가, 역산하는가, 여러 경우를 비교하는가?”

## 0. 분석 도구를 먼저 구분한다

분석작업은 기능 이름이 비슷해 보이지만 해결하는 문제가 서로 다르다.

| 문제 | 도구 |
|---|---|
| 행의 순서를 바꾼다 | Sort |
| 그룹별 합계/평균을 만든다 | Subtotal |
| 여러 범위를 하나로 합친다 | Consolidate |
| 원하는 결과가 되도록 입력 하나를 찾는다 | Goal Seek |
| 입력 1~2개 변화에 따른 결과표를 만든다 | Data Table |
| 여러 입력값 세트를 저장·비교한다 | Scenario |
| 대량 데이터를 축별로 요약한다 | PivotTable |

→ Đừng học từng nút riêng lẻ. Hãy học theo “loại câu hỏi mà công cụ giải quyết”.

---

# 1. 정렬 — Sort

정렬은 row 순서를 특정 기준으로 재배치한다.

## 1.1 Single-level sort

예:
점수 내림차순.

## 1.2 Multi-level sort

예:
1. 부서 오름차순
2. 같은 부서 안에서 점수 내림차순

### 실전 포인트

정렬은 선택한 column만 움직이는 것이 아니라 **record 전체 행이 같이 이동해야 한다**.

→ Nếu chỉ sort một column riêng lẻ, quan hệ giữa các field trong cùng record có thể bị phá vỡ.

---

# 2. 부분합 — Subtotal

Subtotal은 정렬된 데이터에서 그룹별 집계를 만든다.

## 2.1 왜 정렬이 먼저 필요한가

부분합은 동일한 그룹이 연속해 있다고 가정하고 group change를 기준으로 계산한다.

따라서:

**Sort by group field → Subtotal**

예:
부서별 매출 합계라면 먼저 부서를 기준으로 정렬한다.

## 2.2 설정 요소

- At each change in → 그룹 기준 field
- Use function → Sum, Average, Count 등
- Add subtotal to → 계산 대상 field

### Outline

Subtotal 결과에는 outline level이 생성되어 detail을 접고 펼칠 수 있다.

### 감점 포인트

- 정렬 안 함
- 그룹 field 선택 오류
- 집계 함수 오류
- 계산 대상 column 오류

---

# 3. 데이터 통합 — Consolidate

Consolidate는 여러 range의 값을 하나의 summary table로 합친다.

예:
서울점, 부산점, 인천점의 동일 형식 매출표를 하나의 total로 합친다.

## 3.1 Position vs Label

데이터 구조가 완전히 같은 위치라면 position 기반 통합이 가능하다.

Row/Column label이 기준이라면 label을 이용해 대응시킬 수 있다.

→ Quan trọng là hiểu “các range được ghép theo vị trí hay theo nhãn”.

## 3.2 대표 함수

- SUM
- AVERAGE
- COUNT
- MAX
- MIN

---

# 4. 목표값 찾기 — Goal Seek

Goal Seek는 이미 formula가 있는 결과 cell을 특정 값으로 만들기 위해 **하나의 input cell**을 역산한다.

구조:

- Set cell → formula result
- To value → 원하는 목표값
- By changing cell → 바꿀 input

예:
이익 = 매출 - 비용이라는 수식이 있을 때, 이익을 1,000,000으로 만들기 위한 판매수량을 찾는다.

### 핵심 제한

Goal Seek는 기본적으로 한 번에 하나의 changing cell을 다룬다.

→ Nếu có nhiều biến đầu vào cần đổi đồng thời, Goal Seek không phải mental model phù hợp.

---

# 5. 데이터 표 — Data Table

Data Table은 하나 또는 두 개의 input 변화에 따른 formula result를 표로 계산한다.

## 5.1 One-variable Data Table

하나의 input 값이 여러 값으로 바뀔 때 결과 변화를 본다.

예:
이자율 2%, 3%, 4%, 5%에 따른 상환액.

## 5.2 Two-variable Data Table

두 input 조합에 따른 결과를 matrix 형태로 본다.

예:
이자율 × 대출기간 조합별 상환액.

### Goal Seek과 비교

- Goal Seek → result를 정하고 input을 찾음
- Data Table → 여러 input을 정하고 result를 비교함

---

# 6. 시나리오 — Scenario

Scenario는 여러 input cell의 값 조합을 이름 붙여 저장하고 비교하는 What-if 도구다.

예:

- 낙관 시나리오: 매출 120, 비용 70
- 기준 시나리오: 매출 100, 비용 75
- 비관 시나리오: 매출 80, 비용 80

→ Scenario phù hợp khi cần so sánh cả một “gói giả định”, không chỉ một biến.

## 6.1 Changing Cells

시나리오마다 달라질 input cell들을 지정한다.

## 6.2 Result Cells

각 시나리오에서 비교할 formula result를 summary로 볼 수 있다.

---

# 7. PivotTable

PivotTable은 큰 list data를 다시 계산하지 않고도 field를 배치해 빠르게 요약하는 도구다.

## 7.1 원본 데이터의 조건

좋은 Pivot source는 다음 특징을 가진다.

- 각 column에 명확한 header
- 한 row = 한 record
- 중간에 불필요한 blank row/column 없음
- 동일 column은 동일 의미의 data type

## 7.2 네 영역

### Rows

세로 group.

### Columns

가로 group.

### Values

SUM, COUNT, AVERAGE 등 집계되는 숫자.

### Filters

전체 Pivot에 적용되는 filter.

## 7.3 예제

원본:

| 날짜 | 지점 | 상품 | 매출 |
|---|---|---|---:|
| 1/1 | 서울 | A | 100 |
| 1/1 | 부산 | A | 80 |
| 1/2 | 서울 | B | 120 |

질문:
“지점별·상품별 매출 합계를 보고 싶다.”

배치:

- Rows → 지점
- Columns → 상품
- Values → 매출 Sum

## 7.4 값 필드 설정

숫자 field가 항상 SUM으로 들어간다고 가정하지 않는다. 데이터 형태에 따라 COUNT 등으로 들어갈 수 있으므로 Value Field Settings를 확인한다.

## 7.5 Refresh

원본 데이터가 바뀌면 PivotTable이 자동으로 항상 즉시 반영된다고 가정하지 않는다. 필요 시 Refresh한다.

---

# 8. PivotChart

PivotChart는 PivotTable 요약 구조와 연결된 chart다.

→ 일반 chart는 cell range를 직접 시각화하고, PivotChart는 Pivot field 구조를 기반으로 움직인다.

실전에서는 먼저 PivotTable 구조가 맞는지 확인한 뒤 chart를 만든다.

---

# 9. 기능 선택 decision tree

문제에서 다음 단어를 찾는다.

## “그룹별 합계”

Subtotal 또는 PivotTable 후보.

판단:
원본 list 안에 outline 형태 summary를 넣는가? → Subtotal  
다른 요약 view를 만드는가? → PivotTable

## “여러 시트/범위 합계”

Consolidate.

## “결과가 100이 되도록 입력값”

Goal Seek.

## “이자율 변화에 따른 결과표”

Data Table.

## “낙관/기준/비관”

Scenario.

## “행/열 field를 배치해 요약”

PivotTable.

# 10. 검증 workflow

분석 도구는 결과가 그럴듯해 보여도 설정이 틀릴 수 있다.

## Sort

record가 깨지지 않았는가?

## Subtotal

group 기준이 정렬되어 있는가?

## Consolidate

source range를 모두 넣었는가?

## Goal Seek

Set Cell이 formula cell인가?

## Data Table

row/column input cell 방향이 맞는가?

## Scenario

changing cells와 result cells가 문제와 일치하는가?

## PivotTable

Rows/Columns/Values/Filters 배치가 지시와 같은가?

---

# 11. 자주 발생하는 감점 패턴

| 실수 | 원인 | 예방 |
|---|---|---|
| Subtotal 전 정렬 누락 | 기능 순서 이해 부족 | Sort → Subtotal 고정 |
| Goal Seek cell 방향 반대 | Set/Changing 혼동 | 결과 cell과 input cell을 말로 먼저 구분 |
| Data Table row/column input 반대 | 표 방향 미확인 | 상단 row vs 왼쪽 column 확인 |
| Scenario input 누락 | changing cells 범위 미확인 | 지시문에서 모든 변수 표시 |
| Pivot Values 집계 방식 오류 | default 믿음 | Value Field Settings 확인 |
| Pivot field 위치 오류 | row/column 역할 혼동 | 먼저 손으로 layout 그리기 |

# 12. Mini Practice

## Practice A — Subtotal

데이터 field:
부서, 이름, 매출

문제:
부서별 매출 평균을 구한다.

순서:
1. 부서 기준 sort
2. Subtotal
3. At each change in = 부서
4. Function = Average
5. Add subtotal to = 매출

## Practice B — Goal Seek

수식:
이익 = 판매량 × 단가 - 고정비

문제:
이익이 500,000이 되도록 판매량을 찾는다.

- Set Cell → 이익 cell
- To Value → 500000
- Changing Cell → 판매량 cell

원본:
날짜 / 지점 / 상품 / 매출

문제:
지점별 상품 매출 합계.

- Rows → 지점
- Columns → 상품
- Values → 매출 Sum
