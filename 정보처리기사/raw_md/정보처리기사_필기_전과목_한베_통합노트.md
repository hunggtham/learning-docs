## 0. Bức tranh toàn bộ kỳ thi

Một hệ thống phần mềm đi qua chuỗi sau:

```text
Yêu cầu của khách hàng
  → phân tích và thiết kế phần mềm
  → cấu trúc dữ liệu, module, thuật toán
  → database và SQL
  → chương trình, hệ điều hành, mạng
  → triển khai, quản lý dự án và bảo mật
```

| Môn | Tên tiếng Hàn | Câu hỏi trung tâm | Cách nhớ |
|---|---|---|---|
| 1 | 소프트웨어 설계 | Xây hệ thống như thế nào? | 요구사항 → 모델링 → 아키텍처 → 모듈 |
| 2 | 소프트웨어 개발 | Viết, kiểm thử và phát hành ra sao? | 자료구조 → 알고리즘 → 테스트 → 패키징 |
| 3 | 데이터베이스 구축 | Lưu và xử lý dữ liệu thế nào? | 모델링 → 정규화 → SQL → 트랜잭션 |
| 4 | 프로그래밍 언어 활용 | Chương trình và môi trường chạy hoạt động thế nào? | 문법 → 자료형 → 제어문 → OS/네트워크 |
| 5 | 정보시스템 구축 관리 | Quản lý dự án, hạ tầng và an ninh ra sao? | 방법론 → 추정 → 일정 → 네트워크 → 보안 |

### Chuỗi học cần nhớ

```text
요구분석
 → 개념적 설계(ERD/UML)
 → 논리적 설계(테이블·모듈)
 → 정규화·알고리즘
 → 구현(C/Java/Python/SQL)
 → 단위·통합·시스템·인수 테스트
 → 패키징·배포·운영
 → 보안·유지보수
```

**하향식(Top-down)** có cùng một tư duy ở nhiều chương: nhìn toàn bộ trước, chia nhỏ dần, xử lý chi tiết sau. Nhưng phải phân biệt:

- `하향식 설계`: thiết kế từ hệ thống lớn xuống module/bảng nhỏ.
- `하향식 통합 테스트`: kiểm thử từ module cấp trên xuống module cấp dưới, dùng `Stub(스텁)`.
- `Top-down decomposition`: phân rã bài toán từ chức năng tổng quát thành chức năng con.

# 1과목 소프트웨어 설계

## 1.1 Phần mềm và vòng đời phát triển

### 소프트웨어 생명 주기 (Software Life Cycle)

Vòng đời là quy trình từ khi hình thành ý tưởng đến khi loại bỏ hệ thống: `요구사항 분석 → 설계 → 구현 → 테스트 → 유지보수`.

| Mô hình | 한국어 핵심 | Giải thích và từ khóa đề thi |
|---|---|---|
| 폭포수 | Waterfall | Các bước tuần tự, tài liệu rõ, khó quay lại; yêu cầu thay đổi không phù hợp. |
| 프로토타입 | Prototype | Làm mẫu nhanh để người dùng xem và phản hồi; hữu ích khi yêu cầu chưa rõ. |
| 나선형 | Spiral | Lặp theo vòng, mỗi vòng có phân tích rủi ro; phù hợp hệ thống lớn/rủi ro cao. |
| 애자일 | Agile | Lặp ngắn, giao sản phẩm sớm, phản hồi và thay đổi liên tục. |
| 점진적 | Incremental | Chia sản phẩm thành các increment, phát triển từng phần có thể sử dụng. |

### 애자일 4가지 가치

`개인과 상호작용 > 프로세스와 도구`, `작동하는 소프트웨어 > 포괄적인 문서`, `고객과의 협업 > 계약 협상`, `변화에 대응 > 계획을 따름`.

Không có nghĩa là bỏ tài liệu hay kế hoạch; vế bên trái được ưu tiên cao hơn khi xảy ra xung đột.

### Scrum và XP

- `Scrum`: `Product Backlog`, `Sprint Backlog`, `Sprint`, `Daily Scrum`, `Product Owner`, `Scrum Master`, `Development Team`.
- `XP`: `Pair Programming(짝 프로그래밍)`, `Test-Driven Development`, `Continuous Integration`, `Refactoring`, `Simple Design`, `Small Release`.
- `Scrum` quản lý quy trình/sprint; `XP` nhấn mạnh kỹ thuật phát triển và chất lượng code.

## 1.2 Phân tích yêu cầu

### 요구사항

- `기능 요구사항(Functional)`: hệ thống phải làm gì: đăng nhập, tìm kiếm, thanh toán.
- `비기능 요구사항(Non-functional)`: phải hoạt động tốt thế nào: hiệu năng, bảo mật, khả năng sử dụng, độ tin cậy, khả năng bảo trì.
- `사용자 요구사항`: ngôn ngữ người dùng hiểu.
- `시스템 요구사항`: mô tả kỹ thuật cho nhà phát triển.

Một yêu cầu tốt phải `명확성(clarity)`, `완전성(completeness)`, `일관성(consistency)`, `검증 가능성(verifiability)`, `추적성(traceability)`.

### CASE và DFD

- `CASE(Computer Aided Software Engineering)`: công cụ hỗ trợ phân tích, thiết kế, code, kiểm thử và quản lý tài liệu.
- `자료 흐름도(DFD)`: biểu diễn `process`, `data flow`, `data store`, `external entity`.
- `자료 사전(DD)`: định nghĩa chi tiết các phần tử dữ liệu; ký hiệu thường gặp `=`, `+`, `{ }`, `[ ]`, `( )`.
- `HIPO`: `Hierarchy plus Input-Process-Output`; thể hiện phân cấp module và input/process/output.

## 1.3 UML và mô hình hóa

`UML(Unified Modeling Language)` là ngôn ngữ mô hình hóa chuẩn, không phải ngôn ngữ lập trình.

### Relationship 핵심

- `연관(Association)`: hai lớp biết/giữ quan hệ với nhau.
- `집합(Aggregation)`: quan hệ whole–part yếu; phần có thể tồn tại độc lập.
- `복합(Composition)`: whole–part mạnh; whole bị hủy thì part thường bị hủy.
- `일반화(Generalization)`: quan hệ kế thừa `is-a`.
- `의존(Dependency)`: một lớp tạm thời sử dụng lớp khác.
- `실체화(Realization)`: lớp thực thi interface.

### Diagram thường thi

| Diagram | 한국어 | Dùng để làm gì |
|---|---|---|
| Use Case | 유스케이스 | Actor và chức năng hệ thống nhìn từ người dùng. `include` là bắt buộc dùng lại; `extend` là hành vi mở rộng có điều kiện. |
| Class | 클래스 | Class, attribute, operation, visibility và quan hệ. |
| Sequence | 순차 | Thứ tự message theo thời gian giữa các object. |
| Activity | 활동 | Luồng công việc, decision, parallel flow. |
| State | 상태 | Các trạng thái và sự kiện làm object chuyển trạng thái. |
| Component | 컴포넌트 | Thành phần phần mềm và dependency khi triển khai. |
| Deployment | 배치 | Node phần cứng và artifact/component được triển khai ở đâu. |

`Stereotype(스테레오 타입)` là nhãn mở rộng UML, thường viết trong `<< >>`, ví dụ `<<interface>>`.

## 1.4 UI và chất lượng

- UI: `CLI`, `GUI`, `NUI`, `OUI`, `VUI`, `TUI`.
- Nguyên tắc: `직관성(intuitiveness)`, `유효성(effectiveness)`, `학습성(learnability)`, `유연성(flexibility)`.
- Thiết kế tốt phải nhất quán, phản hồi rõ, giảm lỗi, dễ học, hỗ trợ người dùng và cho phép quay lại thao tác sai.
- `품질 요구사항`: chức năng phù hợp, độ tin cậy, khả năng sử dụng, hiệu quả, khả năng bảo trì, khả năng di chuyển.

## 1.5 Kiến trúc phần mềm và thiết kế

### 하향식 설계 và 상향식 설계

- `하향식`: bắt đầu từ chức năng lớn, phân rã thành chức năng nhỏ; dễ kiểm soát mục tiêu tổng thể.
- `상향식`: xây các module nhỏ trước rồi ghép thành hệ thống; thích hợp khi có thành phần tái sử dụng.
- `상위 설계`: kiến trúc, interface, dữ liệu tổng thể.
- `하위 설계`: module, class, logic và thuật toán chi tiết.

### Nguyên tắc kiến trúc

`추상화(Abstraction)`, `캡슐화(Encapsulation)`, `정보 은닉(Information hiding)`, `모듈화(Modularity)`, `계층화(Hierarchy)`.

### Chất lượng kiến trúc

`성능`, `보안성`, `가용성`, `변경 용이성`, `사용성`, `테스트 용이성`, `확장성`, `유지보수성`.

### Architectural patterns

- `Layered`: chia tầng, tầng trên dùng tầng dưới.
- `Client–Server`: client yêu cầu, server cung cấp dịch vụ.
- `Pipe–Filter`: dữ liệu đi qua chuỗi filter; output của filter trước là input của filter sau.
- `MVC`: `Model` dữ liệu/nghiệp vụ, `View` hiển thị, `Controller` nhận input và điều phối.
- `Repository`: dữ liệu tập trung trong repository, các thành phần truy cập qua đó.

## 1.6 OOP, module và code

- `객체(Object)`: trạng thái + hành vi + identity.
- `클래스(Class)`: khuôn mẫu tạo object.
- `캡슐화`: gom dữ liệu và method, che giấu chi tiết.
- `상속`: lớp con nhận thuộc tính/hành vi lớp cha.
- `다형성`: cùng interface/message nhưng hành vi khác nhau.
- `결합도(Coupling)`: mức phụ thuộc giữa module; **thấp càng tốt**.
- `응집도(Cohesion)`: mức liên quan bên trong module; **cao càng tốt**.

Thứ tự 결합도 từ xấu đến tốt thường nhớ: `내용 → 공통 → 외부 → 제어 → 스탬프 → 자료`; 응집도 từ xấu đến tốt: `우연적 → 논리적 → 시간적 → 절차적 → 교환적 → 순차적 → 기능적`.

- `Fan-in`: số module gọi module hiện tại.
- `Fan-out`: số module được module hiện tại gọi.
- `N-S chart`: biểu diễn cấu trúc điều khiển bằng hộp lồng nhau.
- `공통 모듈`: module được nhiều nơi dùng; cần độc lập, rõ interface, dễ kiểm thử.
- `재사용`: dùng lại class, function, component, framework hoặc platform.

### Design Pattern

| Nhóm | Mẫu cần nhớ |
|---|---|
| 생성 | Abstract Factory, Builder, Factory Method, Prototype, Singleton |
| 구조 | Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy |
| 행위 | Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor |

Mẹo: `Singleton` chỉ tạo một instance; `Adapter` làm hai interface không tương thích nói chuyện được; `Observer` thông báo nhiều object khi subject thay đổi; `Strategy` thay đổi thuật toán linh hoạt.

## 1.7 Xác minh yêu cầu và liên kết hệ thống

- `요구사항 검토`: review tài liệu, kiểm tra mơ hồ/thiếu/mâu thuẫn.
- `프로토타이핑`: tạo mẫu để xác nhận với user.
- `모델 검증`: kiểm tra model có phản ánh đúng yêu cầu không.
- `인수 테스트`: người dùng/khách hàng xác nhận hệ thống chấp nhận được.
- `EAI`: tích hợp các ứng dụng trong một doanh nghiệp.
- `ESB`: bus trung tâm, loose coupling, tích hợp service và message.
- `JSON`: nhẹ, key–value/array, phổ biến trong REST.
- `XML`: có tag, hỗ trợ cấu trúc và validation.
- `AJAX`: trao đổi dữ liệu bất đồng bộ, cập nhật một phần trang.
- `APM`: theo dõi hiệu năng và lỗi của ứng dụng.

# 2과목 소프트웨어 개발

## 2.1 Cấu trúc dữ liệu

| Cấu trúc | Đặc điểm |
|---|---|
| 배열(Array) | truy cập theo index nhanh, kích thước thường cố định |
| 연결 리스트 | node chứa data + link; chèn/xóa dễ, truy cập tuần tự |
| 스택(Stack) | LIFO; `push`, `pop`; dùng call stack, undo, biểu thức |
| 큐(Queue) | FIFO; `enqueue`, `dequeue`; dùng scheduling, buffer |
| 데크(Deque) | thêm/xóa ở cả hai đầu |
| 트리(Tree) | phân cấp; binary tree mỗi node tối đa 2 con |
| 그래프(Graph) | vertex + edge; có hướng/vô hướng |

Số cạnh tối đa: graph vô hướng `n(n−1)/2`, graph có hướng `n(n−1)` (không tính self-loop). Cây có `n` đỉnh luôn có `n−1` cạnh.

## 2.2 Thuật toán và độ phức tạp

- `Big-O`: giới hạn tăng trưởng khi input lớn; bỏ hằng số và thành phần bậc thấp.
- `O(1)`: constant; `O(log n)`: binary search; `O(n)`: duyệt một lần; `O(n log n)`: merge/heap/quick trung bình; `O(n²)`: bubble/insertion/selection trường hợp thường.
- `순환 복잡도`: `V(G)=E−N+2` với một connected graph, hoặc `V=E−N+2P` khi có nhiều component; cũng bằng số decision + 1.

### Sorting và search

| Thuật toán | Điểm thi |
|---|---|
| 선택 정렬 | chọn min/max đưa về vị trí; `O(n²)` |
| 삽입 정렬 | chèn phần tử vào đoạn đã sắp xếp; tốt khi gần sorted |
| 버블 정렬 | đổi hai phần tử kề nhau; `O(n²)` |
| 퀵 정렬 | pivot, partition; trung bình `O(n log n)`, xấu `O(n²)` |
| 합병 정렬 | chia rồi merge; `O(n log n)`, cần bộ nhớ phụ |
| 힙 정렬 | max/min heap; `O(n log n)` |
| 이분 검색 | dữ liệu phải sorted; mỗi lần chia đôi |
| 해싱 | key → address; collision xử lý bằng chaining/open addressing |

## 2.3 Module, DBMS và IPC

- `단위 모듈`: đơn vị nhỏ nhất có thể biên dịch/kiểm thử.
- `IPC`: giao tiếp giữa process: pipe, message queue, shared memory, semaphore, socket.
- `DBMS`: tạo, lưu, truy vấn, bảo vệ dữ liệu; ưu điểm giảm dư thừa và hỗ trợ độc lập dữ liệu; nhược điểm chi phí, phức tạp và cần tài nguyên.
- `스키마`: `외부 스키마` (view user), `개념 스키마` (logic toàn DB), `내부 스키마` (lưu trữ vật lý).

## 2.4 Test

### Theo code và theo hành vi

- `화이트박스`: biết code, kiểm tra logic bên trong: statement, branch, condition, condition/decision, multiple condition, basis path.
- `블랙박스`: không biết code, kiểm tra input/output: equivalence partitioning, boundary value, cause–effect graph, error guessing, decision table, state transition.

### Theo thời điểm và giai đoạn

- `검증(Verification)`: làm đúng sản phẩm theo đặc tả không?
- `확인(Validation)`: làm đúng sản phẩm người dùng cần không?
- `단위 테스트`: module riêng.
- `통합 테스트`: interface/interaction giữa module.
- `시스템 테스트`: toàn hệ thống.
- `인수 테스트`: khách hàng/người dùng chấp nhận.
- `회귀 테스트`: sửa đổi xong kiểm tra chức năng cũ không hỏng.

### Top-down và Bottom-up

| Hướng | Cách đi | Module giả |
|---|---|---|
| 하향식 | 상위 → 하위 | `Stub`: giả lập module cấp dưới |
| 상향식 | 하위 → 상위 | `Driver`: gọi module cấp dưới |
| 빅뱅 | tích hợp toàn bộ một lần | khó xác định lỗi |
| 샌드위치 | kết hợp top-down + bottom-up | dùng cả stub/driver |

`테스트 오라클`: tiêu chuẩn xác định kết quả đúng; `참 오라클` biết đáp án đầy đủ, `샘플링 오라클` kiểm tra mẫu, `휴리스틱 오라클` dựa trên kinh nghiệm, `일관성 검사 오라클` so sánh trước/sau.

`테스트 하네스` gồm test driver, test stub, test case, test data, test result và tool quản lý.

## 2.5 Package, build và configuration management

- `IDE`: editor, compiler, debugger, build tool tích hợp.
- `Build`: compile, link, test và tạo artifact.
- `Maven`: `pom.xml`; `Gradle`: DSL, dependency và task linh hoạt; `Jenkins`: CI/CD automation.
- `릴리즈 노트`: phiên bản, thay đổi, lỗi đã sửa, hạn chế, ngày phát hành, người liên hệ.
- `DRM`: bảo vệ bản quyền bằng encryption, key management, quyền sử dụng, xác thực và tracking.
- `형상 관리`: nhận diện configuration item, version control, change control, status accounting, audit.
- `SVN`: centralized client/server; `Git`: distributed repository, branch/merge, local commit.

# 3과목 데이터베이스 구축

## 3.1 Thiết kế database theo 하향식

`요구조건 분석 → 개념적 설계(ERD) → 논리적 설계(관계 스키마) → 정규화 → 물리적 설계(인덱스/저장) → 구현(DDL)`.

- `개념적 설계`: entity, attribute, relationship; không phụ thuộc DBMS.
- `논리적 설계`: relation/table, primary key, foreign key, data type logic.
- `물리적 설계`: record layout, index, partition, storage, access path.

## 3.2 E-R và relational model

- `Entity`: đối tượng tồn tại trong domain.
- `Attribute`: đặc điểm của entity.
- `Relationship`: liên kết giữa entity.
- Cardinality: `1:1`, `1:N`, `N:M`.
- Quan hệ `N:M` thường tách thành bảng trung gian có hai foreign key.
- `릴레이션`: table; `튜플`: row; `속성`: column; `도메인`: tập giá trị hợp lệ.
- Đặc điểm relation: không có tuple trùng, thứ tự row/column không quan trọng, mỗi ô atomic.

### Keys và integrity

- `슈퍼키`: định danh duy nhất, có thể dư cột.
- `후보키`: superkey tối thiểu.
- `기본키`: candidate key được chọn.
- `대체키`: candidate key không được chọn làm primary.
- `외래키`: tham chiếu primary/candidate key của bảng khác.
- `개체 무결성`: primary key không NULL.
- `참조 무결성`: foreign key phải NULL hoặc khớp key được tham chiếu.
- `도메인 무결성`: giá trị thuộc domain.

## 3.3 Quan hệ đại số

- `Select(σ)`: chọn row theo điều kiện.
- `Project(π)`: chọn column, loại trùng.
- `Join`: nối relation theo điều kiện chung.
- `Union(∪)`: hợp, hai relation phải union-compatible.
- `Intersection(∩)`: giao.
- `Difference(−)`: hiệu.
- `Cartesian product(×)`: tích Descartes.
- `Division(÷)`: tìm đối tượng liên quan đến **tất cả** phần tử của relation kia.
- `관계해석`: mô tả điều kiện kết quả cần tìm thay vì chỉ rõ từng bước tính.

## 3.4 Chuẩn hóa và 이상

### Bối cảnh

Bảng quá lớn làm lặp dữ liệu và gây `삽입 이상`, `갱신 이상`, `삭제 이상`. Chuẩn hóa là tách bảng dựa trên dependency để mỗi sự thật được lưu đúng nơi.

### 함수적 종속

`A → B`: biết A xác định duy nhất B. Bên trái là `결정자(determinant)`.

### 1NF–5NF/BCNF

| Dạng chuẩn | Điều kiện | Câu nhớ tiếng Hàn |
|---|---|---|
| 1NF | mỗi ô atomic, không repeating group | `도메인이 원자값` |
| 2NF | 1NF + không phụ thuộc từng phần vào khóa ghép | `부분 함수 종속 제거` |
| 3NF | 2NF + không phụ thuộc bắc cầu | `이행적 함수 종속 제거` |
| BCNF | mọi determinant phải là candidate key | `결정자는 후보키` |
| 4NF | loại multivalued dependency | `다치 종속 제거` |
| 5NF | loại join dependency không cần thiết | `조인 종속성` |

Mẹo `도부이결다조`: `도`메인 원자값 → `부`분 → `이`행 → `결`정자 → `다`치 → `조`인.

Ví dụ:

```text
수강(학번, 과목코드, 학생이름, 과목명, 성적)
PK=(학번, 과목코드)
학번→학생이름, 과목코드→과목명, (학번,과목코드)→성적
```

`학생이름`, `과목명` chỉ phụ thuộc một phần khóa ghép ⇒ vi phạm 2NF. Tách `학생`, `과목`, `수강`.

Nếu `과목코드→교수번호` và `교수번호→교수명`, thì `과목코드→교수명` là bắc cầu ⇒ vi phạm 3NF.

## 3.5 반정규화 và tối ưu

- `반정규화`: cố ý thêm dư thừa/tích hợp bảng để tăng tốc đọc, đổi lại chi phí cập nhật và nguy cơ anomaly.
- Cách làm: tích hợp relation, phân tách relation, thêm thuộc tính dư, thêm derived column, thêm summary table.
- `Index`: primary, unique, secondary; clustered/non-clustered tùy DBMS. Index tăng tốc tìm kiếm nhưng tốn storage và làm INSERT/UPDATE chậm.
- `View`: bảng ảo từ query; bảo mật và đơn giản hóa truy vấn, không nhất thiết lưu dữ liệu riêng.
- `Partition`: chia bảng lớn theo range/list/hash để quản lý và truy vấn tốt hơn.
- `분산 DB`: dữ liệu ở nhiều node; mục tiêu transparency, availability, performance, scalability và reliability.

## 3.6 Transaction và concurrency

`Transaction` là đơn vị công việc logic: hoặc hoàn thành toàn bộ hoặc không có phần nào.

| ACID | 한국어 | Ý nghĩa |
|---|---|---|
| Atomicity | 원자성 | all-or-nothing |
| Consistency | 일관성 | giữ integrity trước/sau |
| Isolation | 독립성 | transaction không ảnh hưởng lẫn nhau |
| Durability | 영속성 | commit rồi không mất |

Trạng thái: `활동 → 부분 완료 → 완료(Commit)` hoặc `실패 → 철회(Rollback)`.

- `COMMIT`: xác nhận thay đổi.
- `ROLLBACK`: hủy thay đổi chưa commit.
- `SAVEPOINT`: điểm quay lại trung gian.
- `CRUD`: Create, Read, Update, Delete; dùng để kiểm tra matrix các entity và function.

## 3.7 SQL cần thuộc

### DDL/DML/DCL/TCL

- DDL: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`.
- DML: `SELECT`, `INSERT`, `UPDATE`, `DELETE`.
- DCL: `GRANT`, `REVOKE`.
- TCL: `COMMIT`, `ROLLBACK`, `SAVEPOINT`.

Thứ tự tư duy SELECT: `FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`.

```sql
SELECT department_id, COUNT(*) AS cnt, AVG(salary) AS avg_salary
FROM employee
WHERE salary >= 3000
GROUP BY department_id
HAVING COUNT(*) >= 2
ORDER BY avg_salary DESC;
```

- `WHERE`: lọc row trước group; `HAVING`: lọc group sau group.
- `COUNT(*)` đếm row; `COUNT(column)` không đếm NULL.
- `DISTINCT`: loại trùng.
- `UNION`: gộp và loại trùng; `UNION ALL`: giữ trùng.
- `INNER JOIN`: chỉ phần khớp; `OUTER JOIN`: giữ cả phần không khớp.
- `IN`, `EXISTS`, `ANY/SOME`, `ALL` dùng trong subquery.
- `NULL`: không phải 0 và không phải chuỗi rỗng; dùng `IS NULL`, không dùng `= NULL`.
- `Trigger`: tự động chạy khi INSERT/UPDATE/DELETE hoặc event; khác procedure ở chỗ trigger thường được DB kích hoạt.
- `ORM`: ánh xạ object ↔ relation; giảm SQL thủ công nhưng có thể phát sinh impedance mismatch/N+1 query.

# 4과목 프로그래밍 언어 활용

## 4.1 Kiểu dữ liệu, biến và toán tử

- `변수`: vùng nhớ có tên, giá trị có thể thay đổi.
- `상수`: giá trị không đổi.
- `자료형`: integer, real, char, string, boolean, array, structure/class.
- Quy tắc tên biến: không bắt đầu bằng số, không dùng keyword, phân biệt hoa thường tùy ngôn ngữ.
- Toán tử: arithmetic, relational, bitwise, logical, assignment, conditional.
- Cẩn thận precedence; `&&`/`and` thường ưu tiên cao hơn `||`/`or`; parentheses để tránh nhầm.

## 4.2 C

- `struct`: nhóm nhiều field có kiểu khác nhau.
- Array: vùng nhớ liên tiếp, index bắt đầu từ 0.
- String C kết thúc bằng `\\0`.
- Pointer lưu địa chỉ; `&x` lấy địa chỉ, `*p` dereference.
- Quan hệ pointer/array: tên array thường suy biến thành địa chỉ phần tử đầu; `a[i] == *(a+i)`.
- Cẩn thận pointer NULL, dangling pointer, out-of-bounds và memory leak.
- `scanf`: truyền địa chỉ biến thông thường bằng `&`; với char array tên mảng đã là địa chỉ.
- `printf` format: `%d`, `%f`, `%c`, `%s`, `%x`.

## 4.3 Java

- primitive vs reference type.
- `class`, `object`, constructor, inheritance, interface, overriding/overloading.
- `public`, `protected`, default, `private`: từ rộng đến hẹp về phạm vi truy cập.
- `try–catch–finally`, `throw`, `throws` xử lý exception.
- Garbage Collector tự thu hồi object không còn reference; không nên tự giả định thời điểm chính xác.
- `System.out.print`, `println`, `printf` là output chuẩn.

## 4.4 Python

- Sequence: `str`, `list`, `tuple`, `range`; index từ 0, negative index từ cuối.
- `list` mutable; `tuple` immutable.
- `dict`: key–value, key phải hashable/unique.
- Slice `a[start:stop:step]`, stop không bao gồm.
- `if/elif/else`, `for`, `while`, `break`, `continue`, `return`.
- `def`: function; `class`: class; `self`: object hiện tại.
- `input()` trả string; cần `int()`, `float()` khi tính toán.
- `is` kiểm tra identity; `==` kiểm tra equality.

## 4.5 Điều khiển và mảng

- `if`: rẽ nhánh theo điều kiện.
- `switch`: nhiều nhánh theo giá trị, chú ý `break` để tránh fall-through.
- `for`: biết số lần hoặc duyệt collection.
- `while`: kiểm tra điều kiện trước; có thể không chạy lần nào.
- `do–while`: chạy ít nhất một lần.
- `break`: thoát loop/switch; `continue`: bỏ phần còn lại của vòng hiện tại.
- Mảng 2 chiều thường truy cập `a[row][column]`; khi tính index phải phân biệt row-major và column-major nếu đề cho.

## 4.6 OS, process và memory

- OS quản lý process, memory, file, I/O, security và resource.
- `Process`: chương trình đang chạy, có address space/resource riêng.
- `Thread`: luồng thực thi trong process; chia sẻ code/data nhưng có stack/register riêng.
- Process state: `생성 → 준비 → 실행 → 대기/블록 → 종료`.
- `PCB`: process state, program counter, registers, scheduling info, memory info, I/O status.
- Scheduling: FCFS, SJF, Round Robin, Priority, HRN, Multilevel Queue/Feedback.
- `Paging`: chia logical memory thành page, physical memory thành frame; giảm external fragmentation nhưng có internal fragmentation.
- `Segmentation`: chia theo logical segment; có thể external fragmentation.
- Page replacement: FIFO, OPT, LRU, LFU, NUR; `Belady anomaly` thường gắn với FIFO.
- `Locality`: temporal, spatial, sequential.
- `Thrashing`: page fault quá nhiều, CPU utilization giảm; liên quan working set và frame allocation.

## 4.7 UNIX/Linux và mạng

- UNIX đặc trưng multi-user, multitasking, portability, hierarchical file system.
- `File descriptor`: số nguyên đại diện file mở; 0 stdin, 1 stdout, 2 stderr.
- Lệnh: `pwd`, `ls`, `cd`, `cp`, `mv`, `rm`, `mkdir`, `rmdir`, `cat`, `grep`, `find`, `chmod`, `chown`, `ps`, `kill`, `man`.
- Environment variables: `PATH`, `HOME`, `USER`, `SHELL`, `PWD`.

### OSI và TCP/IP

OSI: `물리 → 데이터링크 → 네트워크 → 전송 → 세션 → 표현 → 응용`.

- Application: HTTP/HTTPS, FTP, SMTP, POP3/IMAP, DNS, DHCP, SSH, Telnet.
- Transport: TCP reliable/connection-oriented; UDP fast/connectionless.
- Network: IP, ICMP, ARP, routing.
- Data link: Ethernet, PPP, MAC.
- IPv4: 32-bit; subnetting chia network/host bằng mask.
- IPv6: 128-bit, address space lớn, auto-configuration, không broadcast theo kiểu IPv4.
- `Subnet`: số host thường `2^h − 2` (trừ network và broadcast trong IPv4 thông thường).

# 5과목 정보시스템 구축 관리

## 5.1 Phương pháp phát triển và tái sử dụng

- `구조적 방법론`: process/data flow, top-down, tài liệu và quy trình rõ.
- `정보공학 방법론`: data-centered, enterprise information architecture.
- `객체지향 방법론`: object/class, encapsulation/inheritance/polymorphism.
- `컴포넌트 기반 방법론(CBD)`: lắp ghép component tái sử dụng.
- `애자일`: lặp ngắn và thích ứng.
- `소프트웨어 재사용`: dùng lại source, class, library, component, framework.
- `재공학`: phân tích hệ thống cũ để sửa, chuyển đổi, tái cấu trúc hoặc tái phát triển.
- `CASE`: tự động hóa các bước phát triển và quản lý.
- `테일러링`: điều chỉnh phương pháp chuẩn cho phù hợp quy mô, rủi ro, tổ chức và môi trường dự án.
- `프레임워크`: cấu trúc tái sử dụng cung cấp control flow và extension point.

## 5.2 Ước lượng phần mềm

- `LOC`: dựa trên số dòng code; dễ hiểu nhưng phụ thuộc ngôn ngữ.
- `COCOMO`: effort dựa trên KLOC; loại `Organic`, `Semi-detached`, `Embedded`.
- `Putnam`: mô hình Rayleigh, liên hệ effort–time–size.
- `Function Point`: đo chức năng người dùng: EI, EO, EQ, ILF, EIF; ít phụ thuộc ngôn ngữ hơn LOC.
- `PERT`: thời gian kỳ vọng `TE=(O+4M+P)/6`.
- `CPM`: tìm critical path; công việc trên critical path có float bằng 0.
- `Gantt`: thanh theo thời gian, dễ theo dõi tiến độ nhưng không thể hiện phụ thuộc sâu như network.

## 5.3 Quản lý dự án và chất lượng

- Quản lý phạm vi, thời gian, chi phí, chất lượng, nhân lực, giao tiếp, rủi ro, mua sắm và stakeholder.
- `ISO/IEC 12207`: quy trình vòng đời phần mềm.
- `CMMI`: maturity level từ initial đến optimizing; đánh giá năng lực quy trình.
- `SPICE(ISO/IEC 15504)`: đánh giá process capability.
- `품질 보증`: phòng ngừa và cải tiến quy trình; `품질 통제`: phát hiện/sửa sản phẩm không đạt.

## 5.4 Mạng và hạ tầng

- `VLAN`: chia LAN logic, giảm broadcast và tăng bảo mật.
- `LAN 표준`: IEEE 802.x; cần phân biệt Ethernet/802.3, wireless/802.11 và token ring/802.5.
- `CSMA/CD`: Ethernet cổ điển phát hiện collision; `CSMA/CA`: wireless tránh collision.
- Routing: `RIP` distance vector, hop count; `OSPF` link state, cost; `BGP` giữa autonomous systems.
- Flow control: stop-and-wait, sliding window.
- `DAS`: storage gắn trực tiếp server.
- `NAS`: file storage qua network.
- `SAN`: storage network tốc độ cao, block-level.
- `Cloud`: IaaS, PaaS, SaaS; public/private/hybrid cloud.
- Công nghệ mới cần nhận diện keyword: IoT, cloud, big data, blockchain, edge computing, digital twin, AI, metaverse, SDN/SDE.

## 5.5 Recovery và deadlock

- `Recovery`: log-based recovery, checkpoint, shadow paging, backup/restore.
- `Deadlock(교착상태)`: mutual exclusion, hold and wait, no preemption, circular wait.
- Xử lý: prevention, avoidance, detection/recovery.
- `Banker's algorithm`: tránh deadlock bằng kiểm tra safe state.

## 5.6 Secure SDLC và bảo mật

### CIA và các yếu tố bảo mật

- `기밀성(Confidentiality)`: chỉ người được phép đọc.
- `무결성(Integrity)`: dữ liệu không bị sửa trái phép.
- `가용성(Availability)`: dịch vụ sẵn sàng.
- Ngoài ra: authentication, authorization, accountability, non-repudiation.

`Secure SDLC` đưa security vào mọi giai đoạn: yêu cầu, thiết kế, triển khai, kiểm thử, vận hành và bảo trì.

### Lỗ hổng và tấn công

- Input validation yếu: SQL Injection, command injection, XSS, buffer overflow.
- Session hijacking: chiếm session ID/cookie; phòng bằng TLS, cookie flag, expiration, rotation.
- `Stack guard/canary`: phát hiện ghi đè stack.
- `DDoS`: nhiều nguồn làm cạn tài nguyên; biến thể gồm SYN flood, UDP flood, HTTP flood, Smurf.
- `IDS`: phát hiện xâm nhập; `HIDS` trên host, `NIDS` trên network.
- `VPN`: tunnel mã hóa qua mạng công cộng.
- `SSH`: remote shell bảo mật, thay Telnet.
- `Secure OS`: access control, reference monitor, trusted computing base.

### Access control

- `DAC`: chủ sở hữu quyết định quyền.
- `MAC`: system/security label quyết định, người dùng không tự đổi.
- `RBAC`: quyền gắn với role.
- `ABAC`: quyền dựa trên attribute và policy.

### Encryption

- `대칭키/개인키`: một key cho encrypt/decrypt; nhanh, vấn đề phân phối key; DES, 3DES, AES, SEED, ARIA, RC4.
- `공개키`: public key + private key; chậm hơn, giải quyết phân phối và hỗ trợ chữ ký; RSA, ECC, Diffie–Hellman.
- `Hash`: một chiều, tạo fixed-length digest; SHA-2/SHA-3; không phải encryption để giải mã.
- `Salt`: chuỗi ngẫu nhiên thêm vào password trước hash, chống rainbow table và hash trùng.
- Chữ ký số: hash message rồi ký bằng private key; kiểm tra bằng public key.

### Authentication

- knowledge: password/PIN;
- possession: token/phone/certificate;
- inherence: fingerprint/face;
- multi-factor kết hợp từ hai nhóm trở lên.

# Bảng phân biệt nhanh khi làm đề

| Dễ nhầm | Phân biệt |
|---|---|
| Verification / Validation | `Verification`: đúng đặc tả; `Validation`: đúng nhu cầu người dùng |
| Stub / Driver | Top-down dùng Stub; Bottom-up dùng Driver |
| WHERE / HAVING | WHERE lọc row; HAVING lọc group |
| DELETE / TRUNCATE / DROP | DELETE xóa row có thể rollback; TRUNCATE xóa toàn bộ data nhanh; DROP xóa cả object |
| Primary / Foreign key | PK định danh row; FK tham chiếu bảng khác |
| 2NF / 3NF | 2NF: partial dependency; 3NF: transitive dependency |
| Coupling / Cohesion | coupling giữa module thấp tốt; cohesion bên trong module cao tốt |
| TCP / UDP | TCP tin cậy, có kết nối; UDP nhanh, không kết nối |
| DAC / MAC / RBAC | owner / label system / role |
| Hash / Encryption | hash một chiều; encryption có key và giải mã được |
| Process / Thread | process độc lập hơn; thread chia sẻ tài nguyên process |
| Paging / Segmentation | page theo kích thước cố định; segment theo ý nghĩa logic |
| Git / SVN | Git phân tán; SVN tập trung |

# Mẹo đọc câu hỏi tiếng Hàn

- `옳은 것은?`: chọn phát biểu đúng.
- `옳지 않은 것은?`, `틀린 것은?`: chọn phát biểu sai.
- `가장 적절한 것은?`: chọn đáp án phù hợp nhất, chú ý từ khóa phạm vi.
- `제거`, `방지`, `최소화`, `증가`: xác định đề hỏi mục tiêu hay đặc điểm.
- `상위/하위`, `외부/내부`, `논리적/물리적`, `정적/동적`, `대칭/비대칭`: thường là cặp đối chiếu quyết định đáp án.
- Đừng chỉ nhìn từ tiếng Anh; đề thường dùng keyword Hàn như `부분 함수 종속`, `이행적 종속`, `무결성`, `응집도`, `결합도`, `스텁`, `드라이버`.

# Chiến lược ôn tập

1. Đọc bản đồ 5 môn để biết khái niệm nằm ở đâu.
2. Học keyword Hàn–Anh trước, sau đó giải thích bằng tiếng Việt.
3. Với mỗi khái niệm, tự trả lời 3 câu: “nó là gì?”, “giải quyết vấn đề gì?”, “dễ nhầm với gì?”.
4. Làm đề và ghi lỗi theo nhóm: thuật ngữ, công thức, code trace, SQL, OS/network, security.
5. Ôn lại bằng chuỗi: `정의 → 특징 → 장단점 → 비교 → ví dụ → bẫy đề thi`.

## Công thức/chuỗi phải thuộc

- `도부이결다조`: 1NF → 2NF → 3NF → BCNF → 4NF → 5NF.
- `요구분석 → 개념설계 → 논리설계 → 물리설계 → 구현`.
- `상위→하위 = Stub`, `하위→상위 = Driver`.
- `ACID = 원자성·일관성·독립성·영속성`.
- `PERT = (O+4M+P)/6`.
- `무방향 최대 간선 = n(n−1)/2`, `방향 최대 간선 = n(n−1)`.
- `2NF = 부분`, `3NF = 이행`, `BCNF = 결정자 후보키`.
