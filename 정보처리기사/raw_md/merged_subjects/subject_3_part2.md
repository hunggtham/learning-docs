|2정규형<br>(2NF)<br>- 1정규형을 만족<br>- 부분 함수 종속성을 제거함<br>- 부분집합 중 원래 자신의 집합을 제외한 것으로 X와 Y를 각각 R의 애트리뷰트<br>집합의 부분 집합이라고할 경우X → Y로 표시<br>|
|3정규형<br>(3NF)<br>- 2정규형을 만족<br>- 이행 함수 종속을 제거<br>- A→B이고,B→C일 때A→C를 만족하는 관계|
|보이스-코드 정규형<br>(BCNF)<br>- 3정규형을 만족<br>- 기본키를 제외하고 후보키가 있는 경우 후보키가 기본키를 종속시키면 분해 (모<br>든 결정자가 후보키 집합에 속해야 함)|
|4정규형<br>(4NF)<br>- BCNF를 만족<br>- 다치 종속을 제거<br>-여러 컬럼들이 하나의 컬럼을 종속시키는 경우 분해하여 다중값(다치)를 제거|
|5정규형<br>(5NF)<br>- 4정규형을 만족<br>- 조인 종속성을 제거<br>- 조인에 의해서 종석성이 발생하는 경우 분해|
|-기보키를 통하지 않는조인 종속 제거|

- **도메인(Domain)**: 하나의 속성이 취할 수 있는 동일 타입의 원자값 집합
- **카디널리티(Cardinality)**: 튜플의 수 (기수, 대응수)
- **디그리(Degree)**: 속성의 수 (차수)

## 172. 릴레이션의 특징

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 관계형 데이터 모델에서 릴레이션이 반드시 유지해야 할 성질
- * 핵심 키워드**: 튜플의 유일성, 튜플의 무순서, 속성의 무순서, 원자값
- * 구조 / 관점 / 분류**: 데이터 무결성 및 구조적 일관성 관점
- * 시험 포인트**: '속성 간의 순서는 중요하지 않다'는 특징 자주 출제
- * 한 문장 설명**: 릴레이션은 동일한 튜플을 포함할 수 없으며 속성값은 더 이상 쪼갤 수 없는 원자값이어야 한다.
- **: 연관 설명**: 171, 174

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **튜플의 유일성**: 모든 튜플은 서로 상이해야 함
- **튜플의 무순서**: 한 릴레이션 내 튜플들 사이에는 순서가 없음
- **속성의 무순서**: 속성들의 나열 순서는 데이터 처리에 영향을 주지 않음
- **속성명의 유일성**: 속성 이름은 유일해야 하나 값은 중복 가능함

## 173. 키(Key)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 튜플을 식별하거나 정렬할 때 기준이 되는 속성
- * 핵심 키워드**: 후보키, 기본키, 대체키, 슈퍼키, 외래키
- * 구조 / 관점 / 분류**: 유일성(Uniqueness)과 최소성(Minimality) 만족 여부
- * 시험 포인트**: 기본키는 NULL 값을 가질 수 없다는 성질(개체 무결성)
- * 한 문장 설명**: 키는 릴레이션에서 특정 튜플을 유일하게 구별할 수 있는 기준 속성을 의미한다.
- **: 연관 설명**: 170, 174

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **후보키**: 유일성과 최소성을 모두 만족하여 기본키가 될 수 있는 속성들
- **기본키**: 후보키 중 선정된 주키로 중복값과 NULL 불가
- **대체키**: 기본키를 제외한 나머지 후보키 (보조키)
- **슈퍼키**: 유일성은 만족하지만 최소성은 만족하지 못하는 키
- **외래키**: 다른 릴레이션의 기본키를 참조하는 속성 집합

## 174. 무결성(Integrity)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: DB 저장 값과 현실의 실제 값이 일치하는 정확성
- * 핵심 키워드**: 개체 무결성, 참조 무결성, 도메인 무결성, 사용자 정의 무결성
- * 구조 / 관점 / 분류**: 데이터 제약 조건에 따른 분류
- * 시험 포인트**: '외래키 값은 참조 릴레이션의 기본키와 같거나 NULL이어야 함'은 참조 무결성
- * 한 문장 설명**: 무결성 규정은 데이터베이스의 정확성과 안정성을 보장하기 위한 제약 조건을 정의한다.
- **: 연관 설명**: 173, 210

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **개체 무결성**: 기본키는 중복되거나 NULL일 수 없음
- **도메인 무결성**: 속성 값은 정의된 도메인 범위 내에 있어야 함
- **참조 무결성**: 참조 불가능한 외래키 값을 가질 수 없음 (CASCADE 등 적용)
- **사용자 정의 무결성**: 사용자가 정의한 특정 제약 조건을 만족해야 함

## 182. 정규화 과정

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 종속성 이론을 토대로 스키마를 더 작은 속성 세트로 쪼개는 단계적 과정
- * 핵심 키워드**: 1NF(원자값), 2NF(부분함수 제거), 3NF(이행함수 제거), BCNF(결정자)
- * 구조 / 관점 / 분류**: 단계별 제약 조건 강화 프로세스
- * 시험 포인트**: 암기 요령 '도-부-이-결-다-조' (도메인, 부분, 이행, 결정자, 다치, 조인)
- * 한 문장 설명**: 정규화는 1정규형부터 5정규형까지 각 단계의 종속성 문제를 해결하며 무결성을 높인다.
- **: 연관 설명**: 179, 181, 183

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **1NF**: 모든 속성의 도메인이 원자값(Atomic)으로 구성됨
- **2NF**: 부분적 함수 종속성을 제거하여 완전 함수 종속 만족
- **3NF**: 이행적 함수 종속성을 제거 ($A \rightarrow B, B \rightarrow C \implies A \rightarrow C$)
- **BCNF**: 모든 결정자가 후보키가 되도록 함
- **4NF**: 다치 종속(Multi-valued Dependency) 제거
- **5NF**: 조인 종속성(Join Dependency) 이용

## 187. 트랜잭션(Transaction)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 데이터베이스 상태를 변환시키는 하나의 논리적 기능을 수행하기 위한 작업 단위
- * 핵심 키워드**: 작업 단위, 병행 제어, 회복 작업, Commit, Rollback
- * 구조 / 관점 / 분류**: 연산들의 집합 및 상태 변환 과정
- * 시험 포인트**: 트랜잭션의 4대 특성(ACID)과 그 의미 연결
- * 한 문장 설명**: 트랜잭션은 한꺼번에 수행되어야 할 일련의 연산들을 묶어 무결성을 보장하는 실행 단위이다.
- **: 연관 설명**: 188, 189

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 데이터베이스 시스템에서 병행 제어 및 회복 작업의 기준이 됨
- 모든 명령이 완벽히 수행되거나(All), 전혀 수행되지 않아야 함(Nothing)
- 사용자의 서비스 요구에 대한 시스템의 응답 상태 변환 과정임

## 189. 트랜잭션의 특성 (ACID)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 트랜잭션의 무결성을 보장하기 위해 반드시 지켜야 할 4가지 성질
- * 핵심 키워드**: 원자성(Atomicity), 일관성(Consistency), 독립성(Isolation), 영속성(Durability)
- * 구조 / 관점 / 분류**: 트랜잭션 안정성 평가 지표
- * 시험 포인트**: 독립성(Isolation) - 트랜잭션 실행 중 다른 연산이 끼어들 수 없음
- * 한 문장 설명**: ACID 특성은 트랜잭션이 성공적으로 완료되었을 때 데이터의 정확성과 영구성 및 독립적 실행을 보장한다.
- **: 연관 설명**: 187

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **원자성**: 모두 반영(Commit)되거나 전혀 반영되지 않음(Rollback)
- **일관성**: 성공 완료 시 언제나 고정 요소와 상태가 일관됨
- **독립성**: 수행 중인 결과는 완료 전까지 타 트랜잭션이 참조 불가
- **영속성**: 완료된 결과는 시스템 고장 시에도 영구적으로 보존됨

## 193. 뷰(View)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 하나 이상의 기본 테이블로부터 유도된, 실제 저장되지 않는 가상 테이블
- * 핵심 키워드**: 가상 테이블, 논리적 독립성, 보안 강화, CREATE/DROP
- * 구조 / 관점 / 분류**: 사용자별 맞춤형 데이터 접근 관점
- * 시험 포인트**: 뷰 자체에 대한 '독립적인 인덱스를 가질 수 없다'는 단점
- * 한 문장 설명**: 뷰는 사용자에게 필요한 데이터만 제한적으로 보여줌으로써 보안을 제공하고 관리를 간편하게 한다.
- **: 연관 설명**: 153, 191

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 물리적으로 존재하지 않으나 사용자에게는 있는 것처럼 간주됨
- 기본 테이블의 기본키를 포함해야 삽입, 삭제, 갱신 연산이 가능함
- 정의 변경은 불가하며 변경 시 삭제 후 재생성해야 함
- 복잡한 쿼리를 단순화하고 데이터 독립성을 제공하는 장점이 있음

## 194. 파티션(Partition)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 대용량 테이블이나 인덱스를 작은 논리적 단위로 나누어 관리하는 기술
- * 핵심 키워드**: 범위 분할(Range), 해시 분할(Hash), 목록 분할(List), 라운드 로빈
- * 구조 / 관점 / 분류**: 데이터 분산을 통한 성능 저하 방지 및 관리 효율 관점
- * 시험 포인트**: 해시 분할은 데이터를 고르게 분산시키지만 위치 판단은 불가함
- * 한 문장 설명**: 파티션은 대용량 DB의 특정 테이블 집중 현상을 해소하여 성능 향상과 쉬운 데이터 관리를 가능케 한다.
- **: 연관 설명**: 166

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **범위 분할**: 날짜 등 열 값의 범위를 기준으로 분할
- **해시 분할**: 해시 함수 결과에 따라 균등 분산 (고객번호 등에 효과적)
- **목록 분할**: 특정 값들의 목록(예: 국가명)을 기준으로 분할
- **라운드 로빈**: 레코드를 균일하게 순차 분배 (기본키 불필요)
- **조합 분할**: 범위 분할 후 다시 해시 분할을 적용하는 방식

## 195. 분산 데이터베이스의 개요

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 물리적으로 분산된 여러 사이트를 네트워크로 연결하여 논리적으로는 하나의 데이터베이스처럼 사용하는 시스템
- * 핵심 키워드**: 분산 처리기, 분산 데이터베이스, 통신 네트워크
- * 구조 / 관점 / 분류**: 자원 공유 및 신뢰성 향상을 위한 분산 구조
- * 시험 포인트**: 사용자에게는 데이터의 물리적 분산이 보이지 않아야 함(투명성)
- * 한 문장 설명**: 분산 데이터베이스는 지리적으로 떨어진 데이터를 유기적으로 연결하여 하나의 논리적 단위로 관리한다.
- **: 연관 설명**: 196

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 여러 곳에 분산된 데이터베이스를 하나의 시스템처럼 운영함
- 자원을 효율적으로 공유하고 시스템의 가용성을 높임
- 논리적으로는 하나로 보이지만 물리적으로는 분산되어 저장됨
- 지역 자치성이 높으며 하드웨어 확장이 용이함

## 196. 분산 데이터베이스의 목표

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 분산 데이터베이스 시스템이 원활하게 작동하기 위해 보장해야 하는 4대 투명성 요소
- * 핵심 키워드**: 위치 투명성, 복제 투명성, 병행 투명성, 장애 투명성
- * 구조 / 관점 / 분류**: 4대 투명성(Transparency) 관점
- * 시험 포인트**: 각 투명성(위치, 복제, 병행, 장애)의 정의를 연결하는 문제 빈출
- * 한 문장 설명**: 분산 데이터베이스는 사용자가 데이터의 위치나 복제 여부를 몰라도 정상적으로 접근할 수 있도록 보장해야 한다.
- **: 연관 설명**: 195

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **위치 투명성**: 데이터의 물리적 저장 위치를 몰라도 접근이 가능함
- **복제 투명성**: 데이터가 여러 곳에 복제되어 있어도 하나의 데이터로 간주함
- **병행 투명성**: 여러 트랜잭션이 동시에 실행되어도 결과의 일관성이 유지됨
- **장애 투명성**: 특정 지역에 장애가 발생해도 시스템 전체는 계속 작동함

## 197. 암호화 (Encryption)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 송신자가 보낸 평문을 수신자 외에는 알 수 없도록 암호문으로 변환하는 보안 기술
- * 핵심 키워드**: 평문(Plaintext), 암호문(Ciphertext), 암호화, 복호화(Decryption)
- * 구조 / 관점 / 분류**: 암호화 알고리즘 및 키 관리 방식
- * 시험 포인트**: 암호화(평문→암호문)와 복호화(암호문→평문)의 개념 구분
- * 한 문장 설명**: 암호화는 데이터 전송 시 정보의 기밀성을 보장하기 위해 평문을 해독 불가능한 형태로 바꾼다.
- **: 연관 설명**: 198, 361

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **평문(Plaintext)**: 암호화되기 전의 읽을 수 있는 데이터
- **암호문(Ciphertext)**: 암호화되어 내용을 알 수 없는 데이터
- 정보 보호를 위해 데이터를 가공하는 핵심 보안 기술임
- 인가된 사용자만이 복호화 키를 사용하여 원래 데이터를 확인할 수 있음

## 198. 개인키 암호 방식 (Private Key Encryption)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 암호화와 복호화에 동일한 키를 사용하는 대칭 암호 방식
- * 핵심 키워드**: 대칭 암호, 단일키, DES, AES, 블록/스트림 암호
- * 구조 / 관점 / 분류**: 블록 암호 방식과 스트림 암호 방식으로 분류
- * 시험 포인트**: 사용자 증가 시 관리해야 할 키의 수가 급격히 늘어나는 단점
- * 한 문장 설명**: 개인키 방식은 속도가 빠르지만, 비밀키를 안전하게 공유하고 관리하는 것이 핵심 과제이다.
- **: 연관 설명**: 197, 331, 332

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **대칭키**: 암호화할 때와 풀 때 똑같은 열쇠를 씀
- **장점**: 알고리즘이 단순하고 데이터 처리 속도가 매우 빠름
- **단점**: 사용자마다 서로 다른 키가 필요하므로 키 분배와 관리가 어려움
- 대표적인 알고리즘으로 **DES**, **AES**, **SEED**, **ARIA** 등이 있음
- 블록 암호는 데이터를 일정 단위로 묶어서 처리하고, 스트림 암호는 비트 단위로 처리함

---

**암호화 방식의 비유**:
**개인키 암호 방식(198)**은 금고의 문을 잠근 열쇠와 여는 열쇠가 똑같은 것과 같습니다. 열쇠 하나만 관리하면 되니 빠르고 편하지만, 금고를 사용하는 사람이 많아지면 각자에게 열쇠를 안전하게 전달하는 것이 큰 문제가 됩니다. 반면 **공개키 방식**은 누구나 잠글 수 있는 자물쇠(공개키)는 외부에 두고, 오직 주인만 가진 열쇠(비밀키)로만 열 수 있는 우체통과 같습니다.

## 199. 접근통제 기술

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 데이터베이스 객체에 대한 접근 권한을 제한하여 비인가된 사용을 통제하는 기술
- * 핵심 키워드**: 임의 접근통제(DAC), 강제 접근통제(MAC), 역할기반 접근통제(RBAC)
- * 구조 / 관점 / 분류**: 데이터 소유자 기준(DAC), 시스템 등급 기준(MAC), 역할 기준(RBAC)
- * 시험 포인트**: DAC는 GRANT/REVOKE를 사용하며, MAC은 주체와 객체의 보안 등급을 비교함
- * 한 문장 설명**: 접근통제 기술은 사용자 식별 및 권한 부여를 통해 데이터베이스 자원을 안전하게 보호한다.
- **: 연관 설명**: 200, 210, 211

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **임의 접근통제(DAC)**: 데이터 소유자가 자신의 판단에 따라 다른 사용자에게 접근 권한을 부여하거나 취소함
- **강제 접근통제(MAC)**: 시스템이 접근 권한을 지정하며, 객체별 보안 등급과 사용자별 인가 등급을 비교하여 제어함
- **역할기반 접근통제(RBAC)**: 중앙관리자가 역할(Role)마다 권한을 부여하고, 사용자는 할당된 역할에 따라 권한을 행사함

## 200. 강제 접근통제(MAC)의 보안 모델

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 군대와 같이 보안 등급이 엄격한 환경에서 기밀성과 무결성을 유지하기 위한 수학적 모델
- * 핵심 키워드**: 벨 라파듈라(Bell-LaPadula), 비바(Biba), 클락-윌슨, 만리장성 모델
- * 구조 / 관점 / 분류**: 기밀성 중심(벨 라파듈라), 무결성 중심(비바, 클락-윌슨)
- * 시험 포인트**: 벨 라파듈라는 기밀성 강조, 비바 모델은 무결성을 보장하는 최초의 모델임
- * 한 문장 설명**: 강제 접근통제 보안 모델은 기밀성과 무결성을 보장하기 위해 상하 보안 레벨을 정의한다.
- **: 연관 설명**: 199

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **벨 라파듈라 모델**: 정보의 기밀성에 따라 군대의 보안 레벨처럼 상하 관계를 구분함
- **비바 무결성 모델**: 벨 라파듈라를 보완하여 비인가자에 의한 데이터 변형을 방지하는 무결성 강조 모델
- **클락-윌슨 모델**: 상업용으로 개발되었으며, 프로그램(소프트웨어)을 통해서만 객체에 접근 가능함
- **만리장성 모델**: 이해 충돌 관계에 있는 객체 간의 정보 접근을 통제함

## 201. DAS (Direct Attached Storage)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 서버와 저장장치를 전용 케이블로 직접 연결하는 저장 방식
- * 핵심 키워드**: 직접 연결, 전용 케이블, 저비용, 확장성 부족
- * 구조 / 관점 / 분류**: 서버-저장장치 1:1 연결 구조
- * 시험 포인트**: 속도가 빠르고 구축이 쉬우나 다른 서버와 파일 공유가 불가능함
- * 한 문장 설명**: DAS는 외장하드처럼 서버에 저장장치를 직접 연결하여 관리하는 가장 단순한 방식이다.
- **: 연관 설명**: 202, 203

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 전용 케이블을 이용하므로 설치 및 운영이 매우 쉽고 비용이 저렴함
- 직접 연결된 서버만 저장장치를 관리하므로 파일 공유 기능이 없음
- 저장 데이터가 적고 확장이 자주 필요 없는 소규모 환경에 적합함

## 202. NAS (Network Attached Storage)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 서버와 저장장치를 네트워크(Ethernet)를 통해 연결하는 방식
- * 핵심 키워드**: 네트워크 연결, 파일 공유, Ethernet 스위치, 성능 저하 가능성
- * 구조 / 관점 / 분류**: TCP/IP 네트워크 기반 공유 저장 구조
- * 시험 포인트**: DAS보다 확장성이 좋으며 여러 서버에서 장소에 상관없이 접근 가능함
- * 한 문장 설명**: NAS는 별도의 파일 관리 기능이 내장되어 네트워크를 통한 파일 수준의 공유를 지원한다.
- **: 연관 설명**: 201, 203

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 별도의 파일 관리 기능이 있는 NAS Storage가 데이터의 입출력을 직접 관리함
- Ethernet 스위치를 이용하므로 유연성이 우수하지만 접속자가 많아지면 성능이 떨어질 수 있음

## 203. SAN (Storage Area Network)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: DAS의 속도와 NAS의 공유 장점을 혼합한 전용 네트워크 저장 방식
- * 핵심 키워드**: 광 채널(FC) 스위치, 광케이블, 고가용성, 고비용
- * 구조 / 관점 / 분류**: 광 채널 기반의 고속 전용 네트워크 구조
- * 시험 포인트**: 높은 트랜잭션 처리에 효과적이며 가용성과 확장성이 매우 뛰어남
- * 한 문장 설명**: SAN은 광 채널 스위치를 사용하여 서버와 저장장치를 고속으로 연결하는 전용망이다.
- **: 연관 설명**: 201, 202

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 여러 개의 저장장치나 백업 장비를 단일화하여 효율적으로 관리할 수 있음
- 초기 설치 시 별도 네트워크 구축이 필요하여 비용이 많이 들고 기존 장비 업그레이드가 필요할 수 있음

## 207. CREATE TABLE

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 구조 / 관점 / 분류**: 테이블 스키마 정의 구조
- * 시험 포인트**: 기본키는 중복 불가 및 NOT NULL이며, 외래키는 참조 무결성(CASCADE)과 연결됨
- * 한 문장 설명**: CREATE TABLE은 속성명, 데이터 타입, 제약 조건을 명시하여 테이블을 생성한다.
- **: 연관 설명**: 173, 174, 204

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **FOREIGN KEY**: 참조할 테이블과 외래키를 지정하며, ON DELETE/UPDATE 옵션을 설정할 수 있음
- **CHECK**: 속성값에 대한 특정 제약 조건을 정의하여 데이터의 유효성을 검사함

## 208. ALTER TABLE

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 이미 생성된 테이블의 정의(구조)를 변경하는 명령문
- * 핵심 키워드**: ADD, ALTER, DROP COLUMN
- * 구조 / 관점 / 분류**: 테이블 구조 수정 관점
- * 시험 포인트**: 새로운 속성 추가(ADD)와 기존 속성의 데이터 타입 변경(ALTER) 구분
- * 한 문장 설명**: ALTER TABLE은 테이블의 열을 추가하거나 기존 열의 기본값 및 속성을 변경한다.
- **: 연관 설명**: 204

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **ADD**: 새로운 컬럼(속성)을 맨 뒤에 추가함
- **ALTER**: 특정 컬럼의 Default 값을 변경하거나 데이터 타입을 재정의함
- **DROP COLUMN**: 불필요해진 특정 컬럼을 삭제함

## 209. DROP

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 스키마, 도메인, 테이블, 인덱스 등 데이터베이스 객체를 삭제하는 명령문
- * 핵심 키워드**: CASCADE, RESTRICT, 완전 제거
- * 구조 / 관점 / 분류**: 객체 파기 및 참조 관계 처리 관점
- * 시험 포인트**: CASCADE는 참조하는 모든 객체를 함께 삭제하며, RESTRICT는 참조 중일 경우 삭제를 취소함
- * 한 문장 설명**: DROP 명령어는 해당 객체를 데이터베이스에서 영구적으로 제거한다.
- **: 연관 설명**: 204, 215

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **CASCADE**: 참조 무결성을 유지하기 위해 해당 테이블을 참조하는 외래키 관계의 모든 데이터를 연쇄 삭제함
- **RESTRICT**: 삭제하려는 객체를 다른 곳에서 참조하고 있으면 삭제가 실행되지 않음
- DML인 DELETE와 달리 테이블 구조 자체를 디스크에서 삭제함

## 210. DCL (Data Control Language) 개념

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 데이터베이스 관리자(DBA)가 보안, 무결성, 병행 제어를 위해 사용하는 통제 언어
- * 핵심 키워드**: 권한 제어, 트랜잭션 제어, 무결성 유지

- * 한 문장 설명**: DCL은 데이터베이스의 자원을 안전하게 관리하기 위해 접근 권한과 작업 확정 여부를 제어한다.

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 데이터베이스의 일관성과 정확성을 보장하기 위한 필수적인 도구임
- **보안**: 비인가된 접근으로부터 데이터를 보호함
- **병행 제어**: 여러 사용자가 동시에 접근할 때 데이터의 일관성을 유지함

---

**데이터베이스 관리의 비유**:
**접근통제 기술(199)**은 건물의 출입문을 누가 열 수 있는지 정하는 보안 시스템과 같습니다. **DAS, NAS, SAN(201~203)**은 데이터를 보관하는 창고를 건물에 직접 붙일지, 네트워크 복도를 통해 연결할지 결정하는 방식입니다. 이때 **DDL(204)**은 창고의 설계도를 그리고, **DML(205)**은 물건을 넣고 빼며, **DCL(206)**은 창고 열쇠를 관리하고 작업이 끝났음을 확정하는 역할을 합니다.

## 211. GRANT / REVOKE

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 데이터베이스 관리자(DBA)가 사용자에게 권한을 부여하거나 취소하기 위한 명령어
- * 핵심 키워드**: WITH GRANT OPTION, GRANT OPTION FOR, CASCADE
- * 구조 / 관점 / 분류**: 권한 부여(GRANT)와 권한 취소(REVOKE)로 구분
- * 시험 포인트**: WITH GRANT OPTION은 부여받은 권한을 다른 사용자에게 다시 부여할 수 있는 권한임
- * 한 문장 설명**: GRANT는 사용 권한을 부여하고, REVOKE는 부여된 권한을 회수하는 제어어이다.
- **: 연관 설명**: 206, 210

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- ALL, SELECT, INSERT, DELETE 등 대상 객체에 대한 세부 권한을 지정함
- **WITH GRANT OPTION**: 사용자가 자기가 받은 권한을 타인에게 전파할 수 있게 허용함
- **GRANT OPTION FOR**: 타인에게 권한을 줄 수 있는 '권한 부여 능력'만 별도로 취소함
- **CASCADE**: 권한 취소 시 해당 사용자가 다른 이에게 연쇄적으로 부여한 권한까지 모두 취소함

## 212. COMMIT

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 트랜잭션이 성공적으로 종료되어 데이터베이스의 일관성 있는 상태를 위해 모든 변경 내용을 반영하는 명령이다.
- * 핵심 키워드**: 트랜잭션 완료, 일관성(Consistency), 물리적 저장, Auto Commit.
- * 구조 / 관점 / 분류**: DCL(데이터 제어어) 및 트랜잭션 관리.
- * 시험 포인트**: 트랜잭션의 성공적 종료 시 수행하며, 수행 결과가 실제 물리적 디스크에 저장된다는 점이 중요하다.
- * 한 문장 설명**: 트랜잭션 작업이 정상적으로 완료되었음을 알리고 변경 내용을 데이터베이스에 영구적으로 확정하는 명령어이다.
-**: 연관 설명: 186, 213

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 트랜잭션이 성공적으로 끝나면 데이터베이스가 새로운 일관성 상태를 유지하도록 돕는다.
- DML문이 성공적으로 완료될 때 자동으로 수행되도록 설정할 수 있는 기능을 제공한다.
- 성공적으로 완료된 트랜잭션 결과는 시스템 고장이 발생하더라도 영구적으로 보존(영속성)되어야 한다.
- 수행된 결과를 실제 물리적 디스크로 저장하여 데이터 무결성을 보장한다.

## 213. ROLLBACK

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- * 개념**: 데이터베이스 조작 작업이 비정상적으로 종료되었을 때 원래의 상태로 복구하는 명령어
- * 핵심 키워드**: 비정상 종료, 원래 상태, 복구, 트랜잭션 취소
- * 구조 / 관점 / 분류**: 트랜잭션 제어 및 데이터 회복 관점
- * 시험 포인트**: COMMIT되지 않은 모든 변경 사항을 취소하고 마지막 커밋 상태로 되돌림
- * 한 문장 설명**: ROLLBACK은 트랜잭션 실행 실패 시 데이터 일관성을 위해 이전 상태로 되돌리는 제어어이다.
- **: 연관 설명**: 188, 189, 212

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 트랜잭션의 원자성(Atomicity)을 보장하기 위한 핵심 도구임
- 작업 중 오류가 발생하면 시스템은 자동으로 롤백을 수행하여 불완전한 데이터 저장을 막음
- DML 작업 후 데이터에 문제가 발견되었을 때 수동으로 실행하여 안전하게 복구함

- * 핵심 키워드**: GROUP BY, HAVING, WINDOW 함수

- * 시험 포인트**: HAVING 절은 GROUP BY에 의해 생성된 그룹에 대한 조건을 지정함

- **WINDOW 함수**: 행과 행 사이의 관계를 정의하여 집계하며 GROUP BY 없이도 분할 처리가 가능함
- **HAVING**: WHERE 절이 개별 행의 조건이라면, HAVING은 집계된 그룹의 조건임

- * 시험 포인트**: UNION은 중복 제거, UNION ALL은 중복을 포함하여 모두 출력함
- * 한 문장 설명**: 집합 연산자는 여러 질의 결과를 합치거나 공통 부분 또는 차이를 추출한다.
- **: 연관 설명**: 176

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- 연산 대상이 되는 각 SELECT문의 속성 개수와 데이터 타입이 반드시 동일해야 함
- **INTERSECT**: 두 결과 집합의 교집합(공통 부분)만 반환함
- **EXCEPT**: 첫 번째 집합에서 두 번째 집합의 요소를 뺀 나머지(차집합)를 반환함

- 조인 조건이 없는 경우 데카르트 곱(CROSS JOIN)이 발생하여 데이터가 폭증할 수 있음

- 이러한 종속성을 분석하고 제거함으로써 데이터의 중복과 이상 현상을 방지할 수 있다.

- '데이터의 데이터'인 메타 데이터(Meta Data)를 관리하는 곳이다.
- 사용자가 직접 수정(Insert, Update, Delete)할 수 없으며 오직 시스템만 접근할 수 있다.
- 데이터 디렉터리는 시스템 카탈로그와 유사하지만 시스템만 접근 가능한 영역을 의미한다.

## 186. 트랜잭션 (Transaction)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 데이터베이스의 상태를 변화시키는 하나의 논리적 기능을 수행하기 위한 작업 단위이다.
- * 핵심 키워드**: 작업 단위, 논리적 단위, ACID, 병행 제어.
- * 구조 / 관점 / 분류**: 한꺼번에 모두 수행되어야 할 일련의 연산들.
- * 시험 포인트**: 트랜잭션의 4대 특성(원자성, 일관성, 독립성, 영속성)이 매우 중요하다.
- * 한 문장 설명**: 데이터베이스 상태를 변환시키는 하나의 논리적 기능을 수행하기 위한 작업 단위이다.
-**: 연관 설명: 187, 188, 189.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 데이터베이스 시스템에서 회복(Recovery)과 병행 제어(Concurrency Control)의 기본 단위가 된다.
- 모든 작업이 성공하면 Commit, 하나라도 실패하면 Rollback을 수행하여 무결성을 유지한다.
- 사용자의 서비스 요구에 대해 시스템이 응답하는 최소한의 논리적 처리 과정이다.

## 188. 트랜잭션의 상태

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 트랜잭션이 실행되는 과정 중 거치게 되는 5가지의 진행 단계를 말한다.
- * 핵심 키워드**: 활동(Active), 완료(Committed), 실패(Failed), 철회(Aborted), 부분 완료(Partially Committed).
- * 구조 / 관점 / 분류**: 트랜잭션 생명 주기(Life Cycle).
- * 시험 포인트**: '부분 완료'는 마지막 연산이 종료된 직후이자 Commit 실행 전인 상태임을 기억해야 한다.
- * 한 문장 설명**: 트랜잭션이 실행되면서 변하는 활동, 완료, 실패, 철회, 부분 완료의 5가지 상태를 말한다.
-**: 연관 설명: 186.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 활동(Active): 트랜잭션이 시작되어 명령들이 수행 중인 상태이다.
- 부분 완료(Partially Committed): 연산은 모두 끝났으나 결과가 물리적 디스크에 저장되기 전이다.
- 완료(Committed): 트랜잭션이 성공적으로 끝나 Commit 연산을 마친 상태이다.
- 철회(Aborted): 비정상적으로 종료되어 Rollback을 수행한 상태이다.

## 190. CRUD 분석

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 프로세스와 데이터베이스 테이블 간의 관계를 생성, 읽기, 갱신, 삭제 관점에서 분석하는 것이다.

- * 시험 포인트**: CRUD 매트릭스를 작성하여 데이터 발생 빈도와 저장되는 데이터 양을 유추할 수 있다.
- * 한 문장 설명**: 데이터베이스 테이블에 변화를 주는 트랜잭션의 CRUD 연산을 매트릭스로 분석하는 것이다.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 행에는 프로세스를, 열에는 테이블을 배치하여 해당 연산을 표시한다.
- 시스템 분석 시 누락된 트랜잭션이나 테이블을 확인하는 용도로 사용된다.
- 각 테이블에 대해 적어도 하나의 C, R, U, D가 존재해야 데이터 설계가 완결된 것으로 본다.

## 191. 인덱스 (Index)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 데이터 레코드에 빠르게 접근하기 위해 <키 값, 포인터> 쌍으로 구성되는 데이터 구조이다.
- * 핵심 키워드**: 키 값, 포인터, 액세스 시간 단축, 물리적 구조.
- * 구조 / 관점 / 분류**: 데이터의 물리적 저장 구조와 밀접한 관계.
- * 시험 포인트**: 레코드 삽입과 삭제가 수시로 일어나는 경우 인덱스 개수를 최소화하는 것이 효율적이다.
- * 한 문장 설명**: 데이터 레코드를 빠르게 접근하기 위해 키 값과 포인터 쌍으로 구성되는 데이터 구조이다.
-**: 연관 설명: 192.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 데이터베이스의 검색 속도를 높이기 위한 색인과 같은 기능이다.
- 인덱스를 통하면 파일의 모든 레코드를 뒤지지 않고도 필요한 데이터를 즉시 찾을 수 있다.
- 데이터 정의어(DDL)인 CREATE, ALTER, DROP 문을 사용하여 관리한다.

## 192. 인덱스의 종류

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 인덱스 컬럼의 구성 방식과 특성에 따라 분류되는 다양한 인덱스 형태이다.
- * 핵심 키워드**: 트리 기반, 비트맵, 함수 기반, 도메인 인덱스.
- * 구조 / 관점 / 분류**: 접근 방식 및 인덱스 키 구성에 따른 분류.
- * 시험 포인트**: 상용 DBMS에서 가장 많이 사용하는 방식은 트리 기반의 B+ 트리 인덱스이다.
- * 한 문장 설명**: 트리 기반, 비트맵, 함수 기반 등 인덱스 컬럼의 데이터 특성에 따라 여러 종류로 나뉜다.
-**: 연관 설명: 191.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 트리 기반(B+ 트리): 인덱스 블록들이 계층적인 트리 구조를 이루며 검색 효율이 좋다.
- 비트맵 인덱스: 데이터를 0 또는 1의 비트로 변환하여 인덱스 키로 사용하는 방식이다.
- 함수 기반 인덱스: 컬럼 값 대신 특정 함수나 수식을 적용한 결과값에 대해 인덱스를 생성한다.
- 도메인 인덱스: 개발자가 필요에 따라 직접 정의하여 사용하는 확장형 인덱스이다.
