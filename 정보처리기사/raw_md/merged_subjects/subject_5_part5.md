## 318. 소프트웨어 재사용 (Software Reuse)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 이미 개발되어 검증된 소프트웨어의 전체나 일부를 다른 소프트웨어 개발 시 다시 사용하는 활동이다.
- * 핵심 키워드**: 비용 절감, 품질 향상, 생산성 증대, 지식 공유.
- * 구조 / 관점 / 분류**: 개발 효율 최적화 전략.
- * 시험 포인트**: 개발 시간 단축과 품질 향상이라는 장점과 시스템 구축 방법의 지식 공유가 일어난다는 점을 기억해야 한다.
- * 한 문장 설명**: 기존의 설계, 코드, 경험을 새 프로젝트에 적용하여 소프트웨어의 신뢰성을 높이고 비용을 줄이는 기법이다.
- **: 연관 설명**: 319, 320.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 재사용을 통해 프로젝트 실패 위험을 줄이고 개발 과정의 시행착오를 최소화할 수 있다.
- 코드뿐만 아니라 요구사항 명세서, 설계서 등 모든 개발 산출물이 재사용 대상이 된다.
- 재사용되는 소프트웨어는 외부 모듈과의 결합도는 낮고 내부 응집도는 높아야 품질이 좋다.
- 새로운 소프트웨어에 적용하기 위해 이미 개발된 기능을 파악하고 최적화하는 과정이 포함된다.

## 319. 소프트웨어 재사용 방법 (합성 vs 생성)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 소프트웨어를 어떤 방식으로 재조립하거나 만들어내느냐에 따른 기술적 접근 분류이다.
- * 핵심 키워드**: 합성 중심(블록), 생성 중심(패턴), 부품 조립.
- * 구조 / 관점 / 분류**: 재사용 구현 메커니즘의 종류.
- * 시험 포인트**: 모듈을 조립하는 '합성 중심'과 추상적 명세를 구체화하는 '생성 중심'의 정의를 짝지어 기억해야 한다.
- * 한 문장 설명**: 소프트웨어 부품을 블록처럼 조립하는 합성 중심 방법과 명세를 바탕으로 프로그램을 만드는 생성 중심 방법이 있다.
- **: 연관 설명**: 318, 317.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 합성 중심(Composition-Based): 전자 칩과 같은 소프트웨어 블록을 만들어 끼워 맞추는 방식으로 블록 구성 방법이라고도 한다.
- 생성 중심(Generation-Based): 추상화된 명세를 바탕으로 자동화 도구 등을 사용하여 코드를 생성하는 패턴 구성 방법이다.
- 합성 중심은 물리적인 결합에 가깝고, 생성 중심은 논리적인 확장성에 중점을 둔다.

## 323. 수학적 산정 기법 (COCOMO, Putnam, FP)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 과거의 유사한 프로젝트 경험과 통계적 데이터를 공식에 대입하여 개발 비용을 예측하는 상향식 산정 기법이다.
- * 핵심 키워드**: 경험적 추정, COCOMO, Putnam, 기능 점수(FP).
- * 구조 / 관점 / 분류**: 비용 및 노력 산정 자동화 모델.
- * 시험 포인트**: 각 모델의 기준(COCOMO-라인수, Putnam-노력분포 곡선, FP-기능 요인 가중치)을 구분하는 문제가 자주 나온다.
- * 한 문장 설명**: 객관적인 수치와 수학적 모델을 활용하여 소프트웨어 개발에 소요되는 인월(Man-Month)과 기간을 계산한다.
- **: 연관 설명**: 322, 324, 326.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- COCOMO: 보헴이 제안했으며, 소프트웨어의 규모(LOC)와 성격에 따라 비용을 산정하는 방식이다.
- Putnam: Rayleigh-Norden 곡선을 기초로 하며, 시간에 따른 인력 배치를 예측하는 생명 주기 예측 모형이다.
- 기능 점수(FP): 입력, 출력, 질의, 파일, 인터페이스 등 기능적 요인별로 가중치를 부여하여 계산한다.
- 수학적 기법은 수작업 산정보다 일관성이 있고 객관적인 결과 도출이 가능하다.

## 336. 소프트웨어 개발 프레임워크

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 소프트웨어 개발에 공통적으로 사용되는 구성 요소와 아키텍처를 일반화하여 제공하는 기반 구조이다.
- * 핵심 키워드**: 스프링, 닷넷, 모듈화, 제어의 역흐름(IoC).
- * 구조 / 관점 / 분류**: 개발 생산성 향상을 위한 반제품 형태의 기반 환경.
- * 시험 포인트**: 프레임워크의 4대 특성인 '모듈화, 재사용성, 확장성, 제어의 역흐름'을 반드시 암기해야 한다.
- * 한 문장 설명**: 프레임워크는 개발자가 핵심 로직 개발에만 집중할 수 있도록 표준화된 설계와 구현 코드를 제공한다.
- **: 연관 설명**: 179, 337.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 모듈화: 캡슐화를 통해 변경의 영향을 최소화하고 품질과 유지보수성을 높인다.
- 재사용성: 이미 검증된 모듈을 제공하여 개발 예산을 절감하고 신뢰성을 확보한다.
- 확장성: 다형성을 통해 인터페이스를 확장함으로써 다양한 기능을 구현할 수 있다.
- 제어의 역흐름(Inversion of Control): 객체 제어권을 개발자가 아닌 프레임워크가 가짐으로써 효율적인 관리가 가능하다.
- 대표적인 예로 자바 기반의 스프링(Spring)과 윈도우 환경의 닷넷(.NET) 등이 있다.
