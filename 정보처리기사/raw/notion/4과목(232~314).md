## 235. JAVA의 데이터 타입 크기

- 개념: JAVA 언어에서 사용하는 표준 데이터 타입과 각 타입별 메모리 크기

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **boolean**: 참(True)과 거짓(False)만을 저장하는 전용 타입

## 241. 비트 연산자

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- 개념: 데이터를 비트(0, 1) 단위로 논리 연산하거나 자릿수를 이동시키는 연산자
- 핵심 키워드: AND(&), XOR(^), OR(|), NOT(~), Shift(<<, >>)

- 한 문장 설명: 비트 연산자는 메모리 공간을 아끼거나 장치 제어 등 정밀한 작업에 사용된다.
- 연관 설명: 233, 235

### TẦNG B – NOTE 보충 (HIỂU SÂU)

- **Shift(<<, >>)**: 비트를 왼쪽이나 오른쪽으로 밀어 2의 거듭제곱을 곱하거나 나눈 효과를 냄
- **~ (NOT)**: 모든 비트를 반전시킴 (0은 1로, 1은 0으로)

## 242. 논리 연산자

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)

- **|| (OR)**: 두 조건 중 하나만 참이어도 참을 반환

- break가 생략되면 다음 case의 문장들이 연달아 실행되는 'Fall-through' 현상이 발생함

- 페이지가 크면 맵 테이블이 작아져 관리 비용은 줄지만 불필요한 데이터까지 메모리에 올라온다.
- 디스크 접근 횟수와 전체적인 입출력 시간을 고려하여 최적의 크기를 정해야 한다.

## 296. 스래싱(Thrashing)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: 페이지 교체 시간이 실제 실행 시간보다 많아져 CPU 이용률이 급격히 떨어지는 현상이다.
- 핵심 키워드: 페이지 부재, 교체 시간 과다, CPU 이용률 저하.
- 구조 / 관점 / 분류: 가상 메모리 시스템의 성능 마비 상태이다.
- 시험 포인트: 다중 프로그래밍의 정도가 너무 높을 때 발생하며 CPU 이용률이 낮아진다.
- 한 문장 설명: 스래싱은 과도한 페이지 교체 작업으로 인해 시스템의 전체 성능이 마비되는 비정상적인 상태이다.
- **: 연관 설명: 293, 290

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 페이지 부재(Page Fault)가 빈번해지면 운영체제는 데이터를 바꾸느라 바빠진다.
- 이를 방지하기 위해 워킹 셋 기법이나 페이지 부재 빈도(PFF) 조절을 사용한다.
- 시스템이 실제 작업보다는 자원 교체에만 힘을 쏟게 되어 이용자가 성능 저하를 크게 느낀다.

## 297. 프로세스(Process)의 정의

- 한 문장 설명: 프로세스는 CPU 자원을 할당받아 시스템 내에서 실제로 활동하고 있는 동적인 실체이다.
- **: 연관 설명: 282, 299

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 운영체제는 각 프로세스의 상태를 PCB에 기록하여 관리하고 스케줄링한다.
- 비동기적 행위를 일으키는 주체이며 여러 사건의 과정으로 정의되기도 한다.

## 299. 프로세스 상태 전이

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: 프로세스가 생성되어 소멸할 때까지 시스템 내에서 거치는 상태 변화 과정이다.
- 핵심 키워드: 준비(Ready), 실행(Run), 대기(Wait), 상태 전이도.
- 구조 / 관점 / 분류: 프로세스의 생명 주기 관리 관점이다.
- 시험 포인트: 주요 3대 상태(준비, 실행, 대기)와 각 상태 간의 전이 조건을 파악해야 한다.
- 한 문장 설명: 운영체제는 자원 효율을 위해 프로세스를 준비, 실행, 대기 상태로 전환하며 제어한다.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- **준비(Ready)**: CPU를 할당받기 위해 기다리는 상태로 실행 준비가 끝난 상태이다.
- **실행(Run)**: 실제로 CPU를 점유하여 명령을 처리하고 있는 상태이다.
- **대기(Wait)**: 입출력 완료 등의 외부 사건이 일어날 때까지 일시적으로 중지된 상태이다.

## 300. 프로세스 상태 전이 관련 용어

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: 프로세스의 상태를 한 단계에서 다른 단계로 변화시키는 동작들을 의미한다.
- 핵심 키워드: Dispatch, Wake Up, Spooling, 시간 초과.
- 구조 / 관점 / 분류: 상태 변화를 유발하는 제어 동작의 분류이다.
- 시험 포인트: 준비 상태에서 실행 상태로 넘어가는 과정을 **디스패치(Dispatch)**라고 한다.
- 한 문장 설명: 프로세스 제어 동작들은 다중 프로그래밍 환경에서 안정적인 자원 할당을 가능케 한다.
- **: 연관 설명: 299

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- **Wake Up**: 입출력 작업이 끝나 대기 상태의 프로세스가 다시 준비 상태로 가는 것이다.
- **시간 초과(Time Run Out)**: 할당된 CPU 시간이 끝나 실행에서 다시 준비 상태로 내려오는 것이다.
- **Spooling**: 입출력 데이터를 디스크에 임시 저장하여 장치 간의 속도 차이를 극복하는 기술이다.

## 305. IP 주소 (IPv4)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: 인터넷에 연결된 모든 컴퓨터 자원을 구분하기 위한 32비트 고유 주소임.
- 핵심 키워드: 32비트, 8비트씩 4부분, 클래스(A~E), 네트워크/호스트 부분.
- 구조 / 관점 / 분류: 주소 범위에 따라 A, B, C, D, E 클래스로 분류됨.
- 시험 포인트: 클래스별 시작 숫자(A: 0~127, B: 128~191, C: 192~223)와 용도 암기.
- 한 문장 설명: IPv4는 숫자로 8비트씩 4부분, 총 32비트로 구성된 인터넷 표준 주소 체계이다.
- 연관 설명: 306, 307

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- A Class는 국가나 대형 통신망에 사용되며 가장 많은 호스트(약 1,600만 개)를 수용함.
- C Class는 소규모 통신망에 적합하며 최대 256개의 호스트를 가질 수 있음.
- D Class는 멀티캐스트(Multicast) 용도로 예약된 주소임.
- 주소는 네트워크 부분과 호스트 부분으로 나뉘어 계층적 관리를 수행함.

## 306. IPv6의 개요

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: IPv4의 주소 부족 문제를 해결하기 위해 개발된 128비트 차세대 주소 체계임.
- 핵심 키워드: 128비트, 주소 확장성, 보안성, 멀티미디어 기능.
- 구조 / 관점 / 분류: IPv4와의 호환성을 고려한 차세대 인터넷 프로토콜임.
- 시험 포인트: IPv4 대비 장점(보안성 향상, 패킷 크기 무제한, PnP 기능).
- 한 문장 설명: IPv6은 주소 부족 문제를 해결하고 보안 및 품질 제어 기능을 향상시킨 주소 체계이다.
- 연관 설명: 305, 307

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 인증 및 보안 기능을 기본적으로 포함하여 IPv4보다 안전함.
- 실시간 흐름 제어 기능을 통해 멀티미디어 서비스 품질을 보장함.
- 패킷 크기를 확장할 수 있어 대용량 데이터 전송에 유리함.
- 자동 네트워크 설정(Plug and Play) 기능을 지원함.

## 307. IPv6의 구성

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: 16비트씩 8부분으로 구성되며, 각 부분을 콜론(:)으로 구분하여 16진수로 표현함.
- 핵심 키워드: 128비트, 16진수 표현, 콜론(:) 구분, 주소 체계(3종).
- 구조 / 관점 / 분류: 유니캐스트, 멀티캐스트, 애니캐스트 3가지 주소 체계로 분류됨.
- 시험 포인트: 주소 체계의 종류(특히 Anycast)와 표현 방식(16비트 x 8부분).
- 한 문장 설명: IPv6은 128비트 주소를 사용하며 유니캐스트, 멀티캐스트, 애니캐스트 방식으로 통신한다.
- 연관 설명: 306

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 유니캐스트(Unicast)는 1대 1 개별 통신에 사용됨.
- 멀티캐스트(Multicast)는 1대 다수 그룹 통신에 사용됨.
- 애니캐스트(Anycast)는 가장 가까운 수신자 1명과 통신하는 방식임.
- 각 블록의 앞자리에 오는 0은 생략 가능하여 주소 표현을 간소화할 수 있음.

## 307. IPv6(Internet Protocol version 6)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 시험 포인트: 주소 길이(128비트)와 각 부분을 콜론(:)으로 구분한다는 점이 IPv4(32비트, 점 구분)와 다르다.
- 한 문장 설명: IPv6는 무한에 가까운 주소 공간을 제공하며 향상된 멀티미디어 기능과 보안성을 지원한다.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 패킷 크기에 제한이 없어 대용량 데이터 전송에 유리하다.
- 인증 및 보안 기능을 프로토콜 내에 기본적으로 포함하고 있다.

## 308. IPv6의 구성

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: IPv6 주소 체계에서 데이터를 전송하는 세 가지 주요 통신 방식이다.
- 핵심 키워드: 유니캐스트, 멀티캐스트, 애니캐스트.
- 구조 / 관점 / 분류: 데이터 전송 대상 및 범위에 따른 분류이다.
- 시험 포인트: 1:1 전송(유니캐스트), 1:N 전송(멀티캐스트), 가장 가까운 1인(애니캐스트)을 구분해야 한다.
- 한 문장 설명: IPv6는 전송 목적에 따라 유니캐스트, 멀티캐스트, 애니캐스트의 세 가지 주소 체계로 운영된다.
- **: 연관 설명: 307

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- **유니캐스트**: 단일 송신자와 단일 수신자 간의 1:1 통신 방식이다.
- **애니캐스트**: 같은 주소를 가진 노드들 중 가장 가까운 노드 하나와 통신하는 방식이다.

## 309. OSI 참조 모델

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- 개념: 서로 다른 시스템 간의 원활한 통신을 위해 ISO에서 제안한 7단계의 국제 표준 프로토콜 계층이다.
- 핵심 키워드: 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층.
- 구조 / 관점 / 분류: 하위 계층(물리, 데이터 링크, 네트워크)과 상위 계층(전송~응용)으로 구분된다.
- 시험 포인트: 각 계층의 주요 기능(예: 전송 계층 - 종단 간 신뢰 전송)을 정확히 연결해야 한다.
- 한 문장 설명: OSI 7계층 모델은 통신 과정을 단계별로 표준화하여 시스템 간 호환성을 보장한다.
- **: 연관 설명: 314

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

## 301. 스레드 (Thread)

- * 핵심 키워드**: 작업 단위, 자원 공유, 멀티스레드, 병행성 증대.

- * 시험 포인트**: 프로세스 간의 통신이 향상되고 기억장치 낭비가 줄어들어 시스템 성능이 향상된다는 점이 핵심이다.
- * 한 문장 설명**: 스레드는 프로세스의 자원을 공유하면서 독립적인 실행 흐름을 가지는 최소 작업 단위이다.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 사용자 수준 스레드와 커널 수준 스레드로 구분되어 운영체제와 라이브러리에 의해 관리된다.
- 스레드 간 통신이 프로세스 간 통신(IPC)보다 빠르고 효율적이다.
- 멀티프로세서 구조에서 각 스레드를 병렬로 실행할 수 있어 처리 속도가 향상된다.
- 프로세스의 생성이나 문맥 교환(Context Switching)보다 오버헤드가 적어 시스템 부하를 줄인다.

## 302. 주요 스케줄링 알고리즘 (FCFS, SJF, HRN)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 준비상태 큐에 도착한 프로세스들에게 CPU를 할당하는 다양한 우선순위 결정 기법이다.
- * 핵심 키워드**: FCFS(FIFO), SJF, HRN, 비선점 스케줄링.
- * 구조 / 관점 / 분류**: CPU 사용권을 강제로 뺏지 않는 비선점형 방식.
- * 시험 포인트**: HRN의 우선순위 계산식인 '(대기 시간 + 서비스 시간) / 서비스 시간'의 결과값이 클수록 우선순위가 높다는 점이 자주 출제된다.
- * 한 문장 설명**: 실행 시간이나 대기 시간을 기준으로 프로세스의 CPU 할당 순서를 정하는 알고리즘들이다.
- **: 연관 설명**: 299, 300.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- FCFS: 먼저 도착한 프로세스가 먼저 처리되는 가장 간단한 방식이나, 긴 작업이 앞서면 대기 시간이 길어진다.
- SJF: 실행 시간이 가장 짧은 작업에 먼저 할당하며, 평균 대기 시간이 가장 적은 최적 알고리즘이다.
- HRN: SJF의 약점인 긴 작업의 불평등(기아 현상)을 보완하기 위해 대기 시간을 고려한다.
- 비선점 방식이므로 한 번 CPU를 할당받으면 작업이 완료될 때까지 다른 프로세스가 뺏을 수 없다.

## 312. 전송 계층의 주요 프로토콜 (TCP, UDP)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: OSI 7계층 중 전송 계층에서 종단 시스템 간의 신뢰성 있는 데이터 전송을 위해 사용되는 프로토콜이다.
- * 핵심 키워드**: TCP(연결형), UDP(비연결형), 흐름 제어, 패킷 전송.
- * 구조 / 관점 / 분류**: 신뢰성 중심(TCP)과 속도 중심(UDP)의 대비.
- * 시험 포인트**: TCP는 양방향 연결 및 흐름 제어를 제공하고, UDP는 단순한 구조로 전송 속도가 빠르다는 차이점을 묻는다.
- * 한 문장 설명**: 신뢰성 있는 통신을 보장하는 TCP와 실시간 전송에 유리한 UDP가 대표적인 전송 계층 규약이다.
- **: 연관 설명**: 309, 311.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- TCP는 가상 회선 방식을 사용하며 순서 제어와 오류 제어 기능을 통해 데이터 무결성을 보장한다.
- UDP는 오버헤드가 적어 스트리밍이나 게임과 같이 연속성이 중요한 서비스에 주로 사용된다.
- RTCP는 RTP 패킷의 전송 품질을 제어하기 위해 주기적으로 정보를 전송하는 보조 프로토콜이다.
- 전송 계층은 투명한 데이터 전송을 가능하게 하여 상위 계층이 하위의 복잡한 구조를 신경 쓰지 않게 한다.

## 313. 인터넷 계층의 주요 프로토콜 (IP, ICMP, ARP)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 네트워크 계층에서 데이터 패킷의 경로 설정과 오류 보고, 주소 변환을 담당하는 프로토콜들이다.
- * 핵심 키워드**: IP(경로 설정), ICMP(오류 제어), ARP(주소 분석), RARP.

- * 한 문장 설명**: 목적지 주소를 기반으로 최적의 경로를 찾고 통신 중 발생하는 문제를 관리하는 프로토콜 집합이다.

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- IP는 비연결형 데이터그램 방식을 사용하여 신뢰성보다는 효율적인 전송에 집중한다.
- ICMP는 통신 중 발생하는 예기치 못한 상황(오류)을 송신측에 알리는 제어 메시지 역할을 한다.
- ARP는 논리적인 IP 주소를 기반으로 실제 하드웨어의 MAC 주소를 찾아낸다.
- IGMP는 멀티캐스트 그룹의 멤버십을 관리하기 위해 라우터와 호스트 사이에서 사용된다.

- 쉘 스크립트: 유닉스/리눅스 계열의 쉘 명령어를 조합하여 만든 관리용 스크립트이다.
- ASP와 JSP: 각각 마이크로소프트와 자바 기반의 서버 측 동적 페이지 생성을 위한 언어이다.

## 284. Locality

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 프로세스가 실행되는 동안 주기억장치의 일부 페이지만을 집중적으로 참조하는 성질을 의미한다.
- * 핵심 키워드**: 시간 구역성, 공간 구역성, 집중 참조, 워킹 셋 기반.
- * 구조 / 관점 / 분류**: 기억장치 관리 이론 및 참조 특성.
- * 시험 포인트**: 시간 구역성(Loop, Stack)과 공간 구역성(Array)의 구체적인 사례를 구분하는 것이 중요하다.
- * 한 문장 설명**: 프로세스가 주기억장치를 액세스할 때 국부적으로 집중되는 성질로 스래싱 방지를 위한 핵심 이론이다.
-**: 연관 설명: 295, 296

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 시간 구역성: 한 번 참조된 페이지는 가까운 시간 내에 다시 참조될 가능성이 높음을 말한다.
- 공간 구역성: 특정 페이지가 참조되면 그 인근 위치의 페이지가 계속 참조될 가능성이 높음을 말한다.
- 스래싱 현상을 방지하기 위해 사용되는 워킹 셋 이론의 논리적 기반이 된다.
- 반복문(Loop), 스택(Stack), 집계용 변수 등은 시간 구역성을 형성하는 주요 요소이다.
- 배열 순회(Array Traversal)나 순차적 코드 실행은 공간 구역성을 형성한다.

## 285. 워킹 셋 (Working Set)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 프로세스가 원활한 수행을 위해 일정 시간 동안 자주 참조하는 페이지들의 집합이다.
- * 핵심 키워드**: 데닝(Denning), Locality 활용, 페이지 부재 감소, 동적 변경.
- * 구조 / 관점 / 분류**: 가상기억장치 성능 관리 모델.
- * 시험 포인트**: 자주 참조되는 워킹 셋을 주기억장치에 상주시킴으로써 시스템을 안정화한다는 점이 핵심이다.
- * 한 문장 설명**: 프로세스의 실행 과정에서 집중적으로 사용되는 페이지 묶음을 메모리에 유지하여 효율을 높이는 기법이다.
-**: 연관 설명: 294, 296

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 데닝(Denning)이 제안한 모델로, 프로그램의 국부성(Locality) 특징을 적극적으로 이용한다.
- 워킹 셋은 시간에 따라 자주 참조하는 페이지가 달라지므로 지속적으로 변경된다.
- 페이지 부재(Page Fault)와 페이지 교체 현상을 줄여 프로세스의 기억장치 사용을 안정화한다.
- 시스템이 워킹 셋을 충분히 수용하지 못하면 스래싱(Thrashing)이 발생하여 성능이 저하될 수 있다.

## 287. UNIX 시스템의 구성

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: UNIX 운영체제를 이루는 핵심 요소인 커널, 쉘, 유틸리티 프로그램의 계층적 구조이다.
- * 핵심 키워드**: 커널(Kernel), 쉘(Shell), 유틸리티(Utility), 계층 구조.
- * 구조 / 관점 / 분류**: 운영체제의 물리적 및 논리적 구성.
- * 시험 포인트**: 커널(핵심 및 상주)과 쉘(명령어 해석기 및 인터페이스)의 역할을 명확히 구분해야 한다.
- * 한 문장 설명**: 하드웨어를 직접 관리하는 커널과 사용자와의 중개자인 쉘 등으로 이루어진 시스템 구조이다.
-**: 연관 설명: 286

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 커널: 하드웨어를 보호하고 프로세스, 기억장치, 파일, 입출력 관리 등 가장 핵심적인 기능을 수행한다.
- 쉘: 사용자의 명령을 인식하여 프로그램을 호출하고 명령을 수행하는 명령어 해석기이다.
- 유틸리티: 에디터, 컴파일러, 디버거 등 사용자가 실제 작업을 수행하기 위해 사용하는 응용 프로그램들이다.
- 커널은 주기억장치에 상주하지만, 쉘은 보조기억장치에서 교체 처리가 가능하다.

## 292. 페이지 교체 알고리즘

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 페이지 부재 발생 시 주기억장치의 모든 프레임이 사용 중일 때 어떤 페이지를 교체할지 결정하는 기법이다.
- * 핵심 키워드**: OPT, FIFO, LRU, LFU, NUR.
- * 구조 / 관점 / 분류**: 가상기억장치 관리 및 자원 할당 전략.
- * 시험 포인트**: 각 알고리즘별 교체 대상 선정 기준(가장 오래된 것, 최근 미사용 등)을 묻는 문제가 자주 출제된다.
- * 한 문장 설명**: 부족한 주기억장치 공간을 확보하기 위해 현재 적재된 페이지 중 하나를 선택하여 교체하는 방법이다.
-**: 연관 설명: 290, 293

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- OPT(Optimal): 향후 가장 오랫동안 사용되지 않을 페이지를 교체하는 가장 이론적으로 효율적인 방식이다.
- FIFO: 주기억장치에 가장 먼저 들어와서 오래 있었던 페이지를 순차적으로 교체한다.
- LRU(Least Recently Used): 현 시점에서 최근에 가장 오랫동안 사용하지 않은 페이지를 교체한다.
- LFU(Least Frequently Used): 참조된 횟수가 가장 적은 페이지를 우선적으로 교체한다.
- NUR: 최근 사용 여부를 확인하기 위해 각 페이지마다 참조 비트와 변형 비트를 활용한다.

## 294. Locality

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 프로세스가 실행되는 동안 주기억장치를 참조할 때 특정 영역의 페이지만 집중적으로 참조하는 성질이다.
- * 핵심 키워드**: 집중 참조, 시간 구역성, 공간 구역성, 스래싱 방지.
- * 구조 / 관점 / 분류**: 기억장치 액세스 패턴 분석.
- * 시험 포인트**: 시간 구역성(시간적 근접성)과 공간 구역성(공간적 근접성)의 차이점을 사례와 연결해야 한다.
- * 한 문장 설명**: 프로세스가 메모리를 참조할 때 국부적으로 편중되는 현상으로 효율적인 메모리 관리의 근거가 된다.
-**: 연관 설명: 295, 296

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 시간 구역성: 한 번 참조된 메모리 위치는 조만간 다시 참조될 가능성이 매우 높다는 이론이다.
- 공간 구역성: 특정 메모리 위치가 참조되면 그 인접한 위치들도 곧 참조될 가능성이 높음을 의미한다.
- 반복문(Loop) 내부의 변수나 스택(Stack)은 시간 구역성의 대표적인 예이다.
- 배열의 순차적 순회나 관련 변수들의 인접 선언은 공간 구역성을 형성한다.
- 이 이론을 바탕으로 자주 쓰이는 페이지를 미리 예측하여 적재함으로써 성능을 향상시킨다.

## 295. 워킹 셋 (Working Set)

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 프로세스가 일정 시간 동안 집중적으로 참조하여 주기억장치에 상주시켜야 하는 페이지들의 집합이다.
- * 핵심 키워드**: 데닝(Denning), 집중 참조 집합, 페이지 부재 최소화, 안정적 실행.
- * 구조 / 관점 / 분류**: 가상기억장치 최적화 전략.
- * 시험 포인트**: 워킹 셋을 메모리에 유지함으로써 페이지 교체로 인한 시스템 과부하를 방지한다는 점이 중요하다.
- * 한 문장 설명**: 프로세스의 원활한 실행을 보장하기 위해 메모리에 반드시 머물러야 하는 핵심 페이지들의 묶음이다.
-**: 연관 설명: 294, 296

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- 프로그램의 Locality(국부성) 특징을 실제 프로세스 관리에 응용한 모델이다.
- 자주 참조되는 페이지 묶음을 주기억장치에 고정시킴으로써 페이지 부재 발생 빈도를 낮춘다.
- 워킹 셋은 고정된 것이 아니라 프로세스 수행 단계에 따라 동적으로 변화하며 관리된다.
- 워킹 셋 관리를 통해 프로세스의 기억장치 사용을 안정화시키고 전체 시스템 성능을 유지한다.

## 298. PCB

### TẦNG A – NOTE NÉN (ÔN / ĐI THI)**

- * 개념**: 운영체제가 각 프로세스를 제어하고 관리하기 위해 필요한 정보를 저장해 두는 데이터 구조이다.
- * 핵심 키워드**: 프로세스 제어 블록, 프로세스 상태, 고유 식별자, 스케줄링 우선순위.
- * 구조 / 관점 / 분류**: 운영체제의 프로세스 관리 핵심 모듈.
- * 시험 포인트**: 프로세스 생성 시 고유하게 생성되며, 종료 시 제거되는 정보 저장소라는 점이 핵심이다.
- * 한 문장 설명**: 운영체제가 프로세스의 현재 상태와 실행 정보를 파악하기 위해 유지하는 전용 제어 블록이다.
-**: 연관 설명: 297, 299

### TẦNG B – NOTE 보충 (HIỂU SÂU)**

- PCB에는 프로세스 식별자, 현재 상태(준비/실행/대기), CPU 레지스터 정보 등이 담겨 있다.
- 부모 및 자식 프로세스에 대한 포인터와 할당된 자원 정보를 포함하여 복잡한 관리를 가능하게 한다.
- 프로세스가 CPU 사용권을 넘길 때 현재까지의 진행 상황을 PCB에 기록하여 나중에 재개할 수 있도록 한다.
- 각 프로세스가 생성될 때마다 고유한 관리 번호와 메모리 위치 정보가 PCB에 할당된다.
